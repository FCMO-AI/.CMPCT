02 / WHY IT CAN WIN

The archive is compiled as an information graph.

CMPCT does not assume that every filename deserves an independent compressed payload. It searches for exact relationships between required objects, chooses physical roots, and records deterministic reconstruction paths while bounding locality and recovery cost.

01

Federate exact streams

Related ZIP-like containers can share identical compressed members globally instead of paying duplicate storage inside each package.

02

Invert representation

If a compressed stream is already required, a matching loose file can be a cheap exact inverse view rather than a second physical payload.

03

Intern identical objects

Snapshots and aliases keep independent logical paths while identical content converges on one authenticated physical root.

04

Bound context

Cross-file context is auditioned rather than assumed, and physical decode units stay bounded to protect selective reads.

05

Separate hot and cold roots

Latency-sensitive inverse views avoid a hidden second decompression layer while colder container streams can share context.

06

Make recovery physical

Redundant authenticated metadata is not decorative: the reader can actually recover through the tail copy after primary corruption.
