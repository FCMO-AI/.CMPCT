00 · PROJECT STATE

The site says what is true now, not what CMPCT hopes to become.

CMPCT is still pre-1.0. The website is continuously validated but deliberately unpublished until a manual release decision. Public project material is separated from private development provenance, and Apache-2.0 is currently a proposal rather than an adopted license.

01 · ENGINE

Compression is one decision inside a larger system.

CMPCT separates the logical filesystem from physical storage. Identical payloads can converge on one blob; large files can be chunked; sparse holes stay holes; nested archives can be treated structurally when that is actually worthwhile.

01

Scan

Read the logical tree, metadata, links, sparse extents and candidate content.

path → object
02

Measure

Probe exact representations and make complexity earn its place.

bytes → evidence
03

Select

RAW, Zstd, Deflate, dictionary, chunks, packs, sparse or virtual structures.

evidence → representation
04

Index

Record the exact reader contract so future readers never need old encoder heuristics.

representation → archive
^

Content-addressed deduplication

Logical names and physical payloads are separate, so repeated exact content is stored once.

^

Range-oriented storage

Fixed/CDC chunks and sparse maps preserve selective reads instead of forcing monolithic inflate.

^

Filesystem semantics

Hardlinks, symlinks, sparse files, ownership and xattrs are data—not incidental baggage.

^

Layered integrity

Cheap hot-path checks coexist with SHA-256 identity and strong verification.

^

Crash-safe generations

Append transactions become committed only at a valid footer; prior generations remain recoverable.

^

Legacy exit, not legacy tax

Export ordinary Deflate ZIP when a downstream system needs it without storing a permanent ZIP shadow.

02 · WORK WITH IT

The reference engine stays boring on purpose.

Install the repository, create an archive, inspect it, verify it, extract it—or export ZIP at the compatibility boundary.

quickstart.sh
python -m pip install -e .
python -m cmpct create ./folder archive.cmpct
python -m cmpct info archive.cmpct
python -m cmpct list archive.cmpct
python -m cmpct verify archive.cmpct
python -m cmpct extract archive.cmpct ./restored
python -m cmpct range archive.cmpct path/to/huge.bin 1048576 4096 -o slice.bin
python -m cmpct export-zip archive.cmpct legacy.zip

06 · FRONTIER

What CMPCT does not get to pretend is finished.

Pre-1.0 breadth is not production readiness. The project keeps the unfinished edges visible so future work attacks the actual gaps.

P0

Defensible parser

Expand golden vectors, fuzzing, structural limits and hostile-input budgets.

P0

Normative format

Determinism, path rules, codec registry, metadata and compatibility policy before 1.0.

P1

Native completeness

Finish remaining representations, streams, extraction, recovery and a shared writer surface.

P1

First-class archive UX

Android, Windows, Apple and Linux integrations backed by one memory-safe core.

P1

Remote + encrypted

Range-backed sources, partial verification and authenticated encryption without inheriting ZIP-era weaknesses.

GATE

Public-release readiness

Resolve licensing, provenance and disclosure review before publication; validate continuously without publishing accidentally.

GATE

Erase honest ZIP advantages

Every reproducible equivalent-semantics loss is a defect, evidence-backed tradeoff or documented platform constraint.
