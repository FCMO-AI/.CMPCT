# CMPCT v0.30 semantic convergence rules

The authoritative v0.30 branch must converge to one semantic owner per promoted responsibility. Research modules may remain for ablation/history, but they must not become competing production implementations.

## Current overlap decisions

- Generic same-filesystem winner publication is owned by the inherited v0.29 scheduler lineage. CMPNX14-specific code may use the same primitive but must not maintain a competing generic implementation.
- Hierarchical Geometry nomination/transform semantics are owned by the CMPNX14 Geometry implementation. Overlay integration should call/reuse that implementation rather than fork separator heuristics.
- PrefixGraph's oracle grammar is evidence scaffolding. The promoted feature must be represented inside the owning canonical v0.30 graph/compiler with dependency depth <=1 and exact complete-artifact pricing.
- GIR hardening semantics—bounded admission, streamed verification/extraction, recovery, rollback—are reader requirements for any promoted new grammar, regardless of which writer path produced the archive.
- Genuine canonical r24 is the product floor for r25 publication on the same original filesystem tree; exact ties retain r24.
- Canonical profile dispatch must be immutable/thread-safe and must not depend on process-global mutation of research modules.

## Working rule

Resolve the current authoritative branch and current `main` immediately before material reconciliation. Preserve provenance for imported research mechanisms, but treat only the exact reconciled candidate and its fingerprint-bound evidence as release authority.

Do not weaken a frozen gate to make convergence pass. Preserve rejected/negative evidence; a losing mechanism can remain useful research without being promoted.

Footnote: semantic convergence optimizes for one explainable product architecture, not minimum source-file count. Duplicate experiments are acceptable; duplicate promoted responsibilities are not.
