## Worldview tested

R40 established a real local R39 speed/byte trade on Incremental Backups but rejected permanent per-family effort policy because the protected family addressed only 0.3685% of the public matrix. R41 tested the concept-compression alternative: whether the existing full-build dictionary effort `12` and transaction effort `9` were accidental duplicate policy state that could be collapsed into one global effort `9` without exporting byte, runtime, RSS, locality, parser, native or platform debt.

The answer is **no** on the frozen public matrix.

Global effort 9 activates materially on three workloads rather than only the R40 backup family, so the experiment did find wider opportunity:

- Analytics/Database;
- Incremental Backups;
- ML Artifacts.

Across the frozen matrix, **218 dictionary-eligible candidates / 10,644,562 raw bytes** were addressable, equal to **4.00217%** of the matrix's 265,969,714 logical bytes. This is a meaningful expansion over R40's narrow family, but the global intervention fails because the added opportunity is not uniformly beneficial.

## Causal interpretation

The split level-12/full-build and level-9/transaction policy is **not demonstrated to be redundant accidental complexity**. Lower dictionary effort has a real speed benefit where dictionaries activate, and it can preserve or even improve bytes on some workloads, but the byte response is workload-dependent. Analytics provides the decisive counterexample: the same global simplification that saves runtime costs 59,149 complete bytes there.

Therefore the correct Forge decision is not to productize a global level 9 and not to invent another scalar level/subset merely to rescue the hypothesis.
