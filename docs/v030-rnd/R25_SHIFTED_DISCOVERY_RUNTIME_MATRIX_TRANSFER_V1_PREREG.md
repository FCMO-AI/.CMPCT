## Question

The exact Shifted A/B proved that the additional position-independent discovery source contributes 397 expensive delta auditions but zero accepted bytes: disabling only `_position_independent_candidates` preserved the exact 1,723,056 B archive and SHA while reducing median child wall 22.41%.

Before a generic R3 deletion is allowed, test the same single ablation across the **entire frozen release-runtime matrix**:

- `resemblance_hostile_v1/01_shifted_versions`
- `neutral_hostile_v1/05_logs_and_telemetry`
- `neutral_hostile_v1/09_ml_artifacts`

The question is deliberately stronger than “does Shifted get faster?”:

> Is the additional discovery source byte-dead across every release-runtime workload where the current attempt-5 builder can execute, so the cleanest product intervention is removal rather than a benchmark-specific admission knob?

## Frozen arms

For each target, two fresh-process alternating paired repetitions:

- **baseline**: unchanged attempt-5 builder;
- **inherited-only**: identical builder with only `accepted.BASE.P._position_independent_candidates` replaced by an empty additional-candidate source.

Inherited `lsh_candidates`, all delta/mosaic primitives, pack planning, candidate scoring, archive grammar, verification, integrity, recovery and locality semantics remain unchanged.

The instrument counts/times `accepted.BASE.P.delta_encode` calls but may not change its inputs or returned bytes.

## Validity

For every target and repetition:

1. strong verification passes;
2. both arms reconstruct the same exact source tree;
3. each arm is byte-deterministic across its two repetitions;
4. positive finite child/delta timings and delta-call counts are recorded;
5. only the frozen discovery-source ablation differs.

Any violation => `INVALID` with zero transfer decision credit.

## Frozen decisions

- `DISCOVERY_SOURCE_RUNTIME_MATRIX_BYTE_DEAD` iff every target has identical baseline/inherited-only archive bytes **and** archive SHA-256, with at least one target reducing delta calls. This authorizes a generic R3 Builder that deletes/neutralizes the source, followed by ordinary product/runtime/generalization receipts.
- `DISCOVERY_SOURCE_TRANSFER_MIXED` iff every arm is valid but at least one target changes archive identity/bytes when discovery is removed. Generic deletion is blocked; preserve the contributing target(s) and next derive a cheap exact admission/futility predicate rather than a workload-name switch.
- `DISCOVERY_SOURCE_RUNTIME_MATRIX_ALTERNATE_SMALLER` iff at least one inherited-only target is strictly smaller and none is larger. Preserve as surprising evidence; hostile review is required before product interpretation.
- `INVALID` otherwise.

For each target report byte delta, archive identities, delta-call reduction fraction, median child-wall ratio and median delta-wall ratio. Timing is causal/supporting evidence only and grants zero release credit.

## Product/carrying-cost law

A matrix-wide byte-dead result favors **concept compression**: delete a globally useless search source instead of adding selector logic. A mixed result forbids corpus-name dispatch and requires a content-derived exact predicate whose global nomination/audition/testing carrying cost is explicitly charged.

No release threshold, comparator, corpus identity, archive grammar, dependency depth, locality/decode-unit bound, integrity/recovery guarantee, memory ceiling or product selector may change in response to this experiment.
