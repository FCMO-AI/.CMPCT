# r25 exact PrefixGraph bounded Zstd-level RSS rehabilitation preregistration

Status: **FROZEN BEFORE RESULT-BEARING EXECUTION**

This Forge experiment follows two accepted facts on frozen Shifted: (1) one live raw-prefix Zstd compression context is a material exact PrefixGraph allocation; (2) precomputed-CDict and fresh-CCtx-per-member lifetime changes do not rehabilitate it. The next justified radicality is to price a small fixed compressor-level ladder explicitly against memory, wall time, and complete PrefixGraph bytes rather than continuing same-semantics lifetime tuning.

## Question

Can a minimally lower Zstd level recover a material fraction of the exact-owner RSS/workspace debt while preserving PrefixGraph grammar, exact reconstruction, the full anchor candidate tournament, and nearly all of the proven byte gain?

This is diagnostic Forge R3 evidence only. It does not alter release thresholds or production source and grants zero release credit.

## Measurement

For each level, run three fresh-process alternating-order complete PrefixGraph builds. Record selected archive bytes/SHA/tree, selected anchor/audition count, total peak `ru_maxrss`, incremental peak for diagnosis, and wall time. The decisive memory comparison uses **total fresh-process peak RSS**, consistent with repository RSS custody law; incremental values are diagnostics only.

Let, relative to level 19:

- `rss_reduction = 1 - candidate_median_total_peak / baseline_median_total_peak`;
- `size_penalty_bytes = candidate_archive_bytes - baseline_archive_bytes`;
- `size_penalty_ratio = size_penalty_bytes / baseline_archive_bytes`;
- `wall_ratio = candidate_median_wall / baseline_median_wall`.

Candidate SHA is not required to equal level 19 because compressor parameters intentionally differ; tree identity, grammar, candidate accounting, strong verification and deterministic repeatability are mandatory.

## Frozen rehabilitation budget

A level is **rehabilitation-qualified** only if all are true:

1. total-peak RSS reduction >= **15%**;
2. complete selected PrefixGraph size penalty <= **8,192 bytes** and <= **0.50%**;
3. wall ratio <= **1.10x**;
4. every repeat at that level is deterministic on archive bytes/SHA and strongly verifies the identical tree.

The 8 KiB / 0.50% byte budget is deliberately much tighter than any release comparator and is not a release-threshold change. Full product no-regression and the unchanged >=687,783 B aggregate release hurdle remain mandatory later.

If multiple levels qualify, choose the **highest level** (smallest intervention). This is frozen before seeing results.

## Terminal decisions

- one or more levels qualify => **`PREFIXGRAPH_LEVEL_REHAB_SUPPORTED`** with the highest qualifying level named; next action is an isolated exact-product Builder/Hostile-Reviewer integration, not immediate production promotion;
- no level qualifies, but at least one produces >=15% RSS reduction => **`PREFIXGRAPH_LEVEL_REHAB_TOO_EXPENSIVE`**; preserve the quantified trade-off and do not tune thresholds post hoc;
- every candidate level produces <15% RSS reduction => **`PREFIXGRAPH_LEVEL_REHAB_INSUFFICIENT`**; compressor level is retired as the next primary workspace lever under this tested ladder and Forge must move to another implementation/workspace boundary.
