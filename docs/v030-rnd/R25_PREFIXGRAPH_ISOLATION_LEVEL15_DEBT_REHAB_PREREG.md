# r25 PrefixGraph process-isolation + level-15 debt rehabilitation preregistration

Status: **FROZEN FORGE R3 / NO RELEASE CREDIT**

## Question

Can the exact Shifted PrefixGraph process-lifetime intervention preserve its previously demonstrated large whole-process-tree RSS reduction while the newly observed level-15 PrefixGraph speed path pays enough of the intervention's exported create-time debt to become a credible productization seed?

This is a rehabilitation experiment, not a reopening of the bounded level ladder as an RSS family. The predecessor results are complementary:

1. exact PrefixGraph process isolation reduced honest whole-process-tree Shifted peak RSS by **27.8478%** but increased create wall time by **17.9814%**, yielding `PROCESS_LIFETIME_BOUNDARY_SUPPORTED_WITH_MAJOR_CREATE_DEBT`;
2. the exact-owner level ladder subsequently showed that level 15 reduced isolated PrefixGraph wall time to **0.6646x** level 19 with only **+61 B** selected PrefixGraph bytes, while changing total exact-owner RSS by only **0.4895%**. The ladder therefore closed as `PREFIXGRAPH_LEVEL_REHAB_INSUFFICIENT` for RSS.

The new worldview is narrower: level 15 is not proposed as a memory fix. It is tested only as a way to rehabilitate the already-evidenced process-lifetime memory win by paying its create-time debt.

## Frozen arms

Every round runs all three arms in rotating order in independent fresh parent processes:

1. **`shipping-l19`** — unchanged current product build, PrefixGraph in the parent at canonical level 19;
2. **`isolated-l19`** — exact accepted process-lifetime topology: one canonical PrefixGraph build in a disposable child at level 19, child exits before G0–G4 continues in the parent;
3. **`isolated-l15`** — identical process-lifetime topology, except the child changes only the raw-prefix dictionary compressor created by PrefixGraph `_prefix_codec` from level 19 to level 15. Direct payload compression remains canonical, dictionary bytes remain raw-content-identical, grammar/anchor nomination/candidate accounting/tie law/reader remain unchanged.

Rounds: **2**, rotating order:

- round 0: shipping-l19 -> isolated-l19 -> isolated-l15;
- round 1: isolated-l15 -> isolated-l19 -> shipping-l19.

The exact same source tree is used for all arms.

## Frozen rehabilitation budgets

Let shipping = median `shipping-l19`, isolated19 = median `isolated-l19`, candidate = median `isolated-l15`.

Candidate **qualifies** only if all are true:

1. `1 - candidate_tree_peak_rss / shipping_tree_peak_rss >= 0.20`;
2. `candidate_wall / shipping_wall <= 1.10`;
3. `candidate_wall / isolated19_wall <= 0.95` — at least 5% same-runner payment of the known isolation create debt;
4. final selected archive byte penalty vs shipping <= **8,192 B** and <= **0.50%**;
5. candidate deterministic across both repetitions and strongly reconstructs the exact source tree;
6. exact process/isolation semantic-owner and lifecycle gates pass.

The 20% memory floor is inherited from the original process-isolation support threshold. The 1.10 wall ceiling is stricter than the predecessor's >1.15 major-debt boundary because this experiment is specifically asking whether the debt has been rehabilitated enough to justify a productization attempt. The size budget matches the bounded level experiment and prevents a speed result from buying itself with material representation loss.
