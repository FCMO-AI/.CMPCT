# r25 shipping-r24 worker-count RSS A/B preregistration

Status: **FROZEN BEFORE RESULT-BEARING EXECUTION**

Predecessor: `R25_R24_PROCESS_LIFETIME_RSS_RESULT.md` established that the genuine canonical r24 build itself reaches roughly 288 MiB on the frozen Shifted target; parent-process/import overhead was retired as the primary explanation. The current shipping r24 builder uses `Builder`'s inherited bounded thread pool, up to eight workers, for independent blob codec competition. This experiment tests whether that existing parallelism materially owns r24's fresh-process high-water.

## Question

Does forcing the exact shipping r24 builder to one encode worker materially reduce total fresh-process peak RSS while preserving exact archive bytes and acceptable diagnostic wall time?

This is a scheduling-only diagnostic. It changes no representation, codec level, dictionary training, Deflate retention, micro-pack policy, CDC policy, locality rule, archive grammar, reader semantics, source identity or release threshold.

## Frozen target and implementation

- target: `resemblance_hostile_v1 / 01_shifted_versions` generated by `benchmarks.v030_release_performance._build_corpora`;
- implementation: `experiments.entropygraph_v030_release_product._locality_bounded_r24_build` including the promoted dead-dictionary post-pass;
- baseline arm: inherited builder worker count;
- candidate arm: same exact shipping path with only `C.Builder(..., workers=1)` forced through a scoped diagnostic subclass;
- repetitions: 3 per arm, every arm in a fresh process, alternating order.

## Exact-output custody

Every repetition must strongly verify. Across all six builds the complete archive length and SHA-256 plus verified logical tree SHA-256 must be identical. The r24 stats must report the same format revision/profile and all representation-affecting release knobs except `encode_workers`. Any output/tree mismatch makes the experiment invalid.

## Frozen metrics

Let:

- `rss_reduction = 1 - median(single_total_peak_rss) / median(inherited_total_peak_rss)`;
- `wall_ratio = median(single_wall_s) / median(inherited_wall_s)`.

Total fresh-process `ru_maxrss` is authoritative because the release performance gate charges total operation peak RSS. Baseline-subtracted high-water is diagnostic only.

## Frozen decision bands

Provided exact-output identity passes:

- `rss_reduction >= 0.20` and `wall_ratio <= 1.25`: **`R24_SINGLE_WORKER_REHAB_SUPPORTED`** — advance to a complete-product A/B; do not change production yet;
- `rss_reduction < 0.05`: **`R24_WORKER_PARALLELISM_RETIRED`** — encode-worker parallelism is not the primary r24 high-water owner;
- otherwise: **`R24_SINGLE_WORKER_AMBIGUOUS`** — preserve evidence and isolate the next allocation/phase before production changes.

A >=20% memory reduction with >25% r24-build wall debt remains ambiguous rather than a win. Complete-product timing remains mandatory before any shipping intervention even if this diagnostic supports the hypothesis.

## Non-borrowable invariants

No benchmark, source, codec, compression level, dictionary bytes/training, file/chunk admission, Deflate reuse, micro-pack, archive grammar, integrity/recovery, locality/decode-unit rule, selected bytes, competitor setting or release state may change. Release credit is **false**.

## Terminal law

If supported, the next experiment must measure the exact complete r25 product with inherited vs one-worker genuine-r24 floor construction, requiring byte-identical selected product output and the unchanged full Shifted runtime/RSS gate. If retired, move to phase/allocation ownership inside r24 construction rather than further scheduler permutations.
