# ONE-G0.2 native writer stage-owner profile — preregistration

Date: 2026-09-07
Branch: `research/cmpct1`
Experimental version: `ONE-G0.2`
Baseline head observed before preregistration: `fd0c6e07d561a2c593a2e8b986842074f5942fbd`

## Mission Lock / Referee

The current positional fused-observation cache has been demoted against the semantically equivalent native fresh observer. General speed work must therefore move upward in scope and identify the dominant cost owner in the best evidenced research-writer envelope before another optimization is attempted.

The profiled envelope is deliberately descriptive first:

`root SHA-256 -> native fresh observation -> relation admission -> native one-pass segmentation -> bounded generic Program construction -> validation -> direct final-buffer canonical emission`

The experiment does not claim that the native observer currently drives relation admission; its cost is charged as the promoted generic discovery/observation stage that a broader ingest path must pay. This prevents the writer benchmark from becoming artificially cheap by omitting discovery entirely.

## Baseline and invariants

Reuse the exact native relation gate, one-pass segment-plan construction, generic ONE Program construction, validation, and growable direct canonical emitter already exercised by the root-hash-charged writer work. Add the promoted native fresh observer as an explicit charged stage.

Hard invariants:

- byte-exact `previous` and `current` reconstruction;
- exact current/previous root SHA-256 values;
- native segment plan agrees with the independent Python oracle whenever relation admission enables the temporal path;
- canonical ONE grammar is unchanged;
- no new reader-visible operation or cache dependency;
- no threshold or admission behavior changes;
- observation semantics are unchanged from the native observer's existing independent-parity evidence.

## Falsifiable hypothesis

With Python fresh observation replaced by the competent native observer, a stable stage or small co-dominant cluster will still own enough of the end-to-end research-writer time to justify a focused next optimization. In particular, a stage is a credible owner only if its median share is at least 20% of total profiled wall time on at least two distinct input families or relation cases at 1 MiB, or if two adjacent stages together exceed 40% consistently.

## Disproof / hold result

Hold owner-directed optimization if no stage reaches the ownership rule above, if ownership changes chaotically across repeated rows, or if instrumentation itself changes semantics. In that case, prefer pass fusion or a broader native writer boundary rather than micro-optimizing one unstable owner.

## Measurement contract

Use deterministic relation cases inherited from the direct-emitter writer benchmark and at least 256 KiB plus 1 MiB roots. For each row run repeated measurements and report median wall and process CPU for:

1. root hashing;
2. native fresh observation;
3. relation admission;
4. native segmentation, when enabled;
5. Program construction;
6. validation;
7. direct canonical emission.

Also report total profiled time, per-stage shares, source traffic exported by the observer/gate/segmenter, modeled segment-plan bytes, Program node count, canonical wire bytes, Surprise bytes, reader work/materialization and exact reconstruction truth.

Stage timing is diagnostic evidence; the normal composed writer remains the authority for whole-path performance. This profiler must not claim that the sum of isolated stage medians equals a production wall-clock benchmark with zero instrumentation overhead.

## Independent evidence and hostile envelope

- Reuse the independent Python segmentation oracle.
- Decode emitted canonical wire through the ordinary ONE decoder/evaluator and require exact outputs.
- Verify root hashes independently with `hashlib.sha256`.
- Preserve enabled productive temporal cases and disabled controls from the existing relation matrix rather than profiling only favorable rows.
- Include the native observer's explicit source/read traffic counters.

## Promotion law

This experiment promotes no format or product mechanism. It may only select the next speed research target.

Terminal decisions:

- `OWNER_<STAGE>` when one stage satisfies the stable ownership rule;
- `OWNER_CLUSTER_<A>_<B>` when an adjacent two-stage cluster satisfies the co-dominant rule while neither stage independently qualifies stably;
- `NO_STABLE_OWNER_FUSE_BOUNDARY` when the profile does not justify isolated stage optimization;
- `INVALIDATE_PROFILE` on semantic/oracle failure.

No timing threshold may be changed after the result to manufacture an owner.
