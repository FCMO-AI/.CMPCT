# ONE-G0.2 — damaged relation Law-expression preregistration

Date: 2026-09-05
Experimental line: ONE-G0.2
Status: frozen before result-bearing execution

## Mission lock

The corrected temporal-adjacency writer gate preserved exact relation admission but showed that complete Python research-writer time erased the isolated dispatch gain. More importantly, 14 of 21 accepted productive relation rows were deliberately left literal because the frozen minimal compiler handled only byte-exact `+1` shifts.

This experiment asks whether the predictive structure already proven by the existing relation dispatcher can be expressed through the **same generic ONE representation**—`surprise`, ranged `Ref`, and `concat`—for damaged accepted relations, without a relation-specific reader opcode or legacy fallback.

This is a representation-viability experiment, not a writer-speed promotion test. Reference-Python construction time is measured diagnostically, but product-speed authority remains native/fused work after semantic viability.

## Falsifiable hypothesis

For the already-frozen quarter-damaged `+1` relation and `fragmented_every96` relation at `4, 8, 16, 32, 64, 128, 256 KiB`, compiling maximal matching runs as ranged references to the previous version and mismatching islands as Surprise will:

1. reconstruct byte-exactly through the existing ONE wire + VM;
2. use fewer stored bytes than the literal two-version baseline on every row;
3. use at most `0.75x` the aggregate literal-baseline wire bytes across the 14 damaged rows;
4. keep incremental control/integrity debt to at most 25% of bytes eliminated on every row;
5. keep full-reader reconstruction work at most `1.75x` the literal baseline on every row;
6. keep materialized bytes at most `1.25x` literal baseline on every row;
7. keep node count bounded by `max(8, ceil(relation_bytes / 64) + 8)` so fragmented structure cannot silently become an unbounded node zoo.

Any violation holds this compiler shape. No density threshold, corpus member, or fragmentation spacing may change after result.

## Frozen corpus

Reuse exactly the relation-transfer generator already used by the temporal writer, but consume only the two damaged productive cases at each frozen size:

- `shift_plus1_damage_quarter`;
- `fragmented_every96`.

Sizes: `4, 8, 16, 32, 64, 128, 256 KiB`.

The dispatcher is not being re-tested here; pair identity and productive relation semantics are inherited from the frozen evidence chain. This test starts at Law expression.

## Baseline

Store the previous and current versions as two ordinary Surprise roots and encode with the current ONE wire.

## Candidate

Use only existing generic ONE operations:

- previous version as an ordinary Surprise node;
- scan the current version under the known `+1` relation;
- each maximal matching run becomes a ranged `Ref` into the previous-version node;
- each maximal mismatch island becomes an ordinary Surprise node;
- one `concat` reconstructs the current root.

No shift opcode, damage opcode, resemblance opcode, opaque codec payload, or reader discovery is permitted.

## Measurements

Per row preserve:

- literal and candidate wire bytes;
- candidate/literal wire ratio and bytes eliminated;
- Surprise bytes;
- control/integrity bytes and incremental control debt;
- node count;
- reader work, materialized bytes, nodes evaluated;
- candidate/literal reader-work and materialization ratios;
- byte-exact round-trip truth.

Also measure interleaved 31-round Python reference construction+wire-encoding time for literal versus generic Law expression. That timing is diagnostic only and must be reported even if ugly; it does not override the representation gates above.

## Referee decision

Advance to a fused/native damaged-relation compiler only if every semantic/resource gate and the aggregate density gate pass. Otherwise preserve the exact failing rows and ask which representation cost owner—control records, fragment node count, or reader work—must be fused or compressed inside the same ONE grammar.

A pass does not establish arbitrary relation discovery, product writer speed, canonical format promotion, or v0.29/v0.30 superiority.
