# ONE-G0.2 Relation Writer Envelope V3 — Preregistration (2026-09-09)

## Mission lock / referee

V2 proved that generic add8/XOR Laws can remove about half the incumbent canonical wire on strongly related versions, but the always-on Python witness path imposed a ~28.96x median CPU tax on controls. V3 tests one causal rehabilitation only: **cheap native opportunity gating before actionable witness construction**.

The promoted incumbent, representation semantics, exact proof boundary, final-wire fallback, and V2 density/economic limits are not weakened.

## Falsifiable hypothesis

The dominant no-op cost in V2 comes from invoking Python actionable-witness discovery on every object even when no useful non-zero relation exists. A native block-cadence pre-gate using three content-derived source/target probes per aligned 64-byte block can preserve required novel relation recall while preventing the expensive witness/proof/Program path from running on ordinary controls.

If this hypothesis is wrong, V3 must HOLD or INVALIDATE rather than move thresholds.

## Candidate

For every two-version object:

1. pay the exact promoted root-hash-charged direct temporal incumbent;
2. run a native paired-version triplet gate at 64-byte block cadence;
3. derive three lanes from the completed block's mixed source/target fingerprint state;
4. a block votes only when all three lanes agree on the same non-zero add8 or XOR value;
5. nominate a family/value only with >=7/8 agreement over eligible blocks;
6. only after a nomination, invoke the existing actionable witness grouping, exact maximal-span proof/growth, generic ONE Program construction, validation and direct canonical emission;
7. preserve the incumbent wire unless the fully validated generic wire is smaller.

The pre-gate never authorizes storage. Exact byte proof remains mandatory.

## Traffic and representation rule

The native pre-gate reads only three source/target pairs per completed 64-byte version block: six probe bytes per 128 bytes of combined two-version input, a fixed **0.046875x combined-input probe ratio**. It does not perform a second full source scan.

V3 is a writer opportunity gate only. It adds no reader opcode, no alternate format and no fallback compressor.

## Frozen matrix

Reuse V2's exact three version sizes and nine families:

- novel: `add8_versioned`, `xor_versioned`, `add8_sparse_cracks`, `xor_sparse_cracks`;
- incumbent preservation: `plus1_incumbent`;
- controls: `exact_repeat`, `random`, `compressed_like`, `probe_false_positive`.

The deliberate `probe_false_positive` continues to poison the old fixed witness probes; V3's lanes are content-derived and therefore must not gain a benchmark-specific fixed-position exception.

## Frozen gates

All V2 gates remain binding:

- exact two-root semantics and SHA-256 root equality: mandatory;
- each novel relation saves at least **25%** canonical wire versus the exact incumbent;
- median novel marginal yield >= **20 Mbit eliminated / additional CPU-second**;
- median control candidate/incumbent CPU <= **1.35x**;
- every individual control CPU ratio <= **1.75x**;
- false-nomination exact proof <= **8,192 bytes**;
- total modeled retained relation state <= **0.60x** combined input;
- expensive witness observation, when invoked, retains its **1.0x** source-scan accounting and <= **0.05x** probe ratio.

Additional V3 gates:

- native pre-gate probe traffic exactly **0.046875x** combined input on aligned rows;
- all twelve novel rows must be nominated with the correct family/value;
- `exact_repeat`, `random`, `compressed_like`, and `plus1_incumbent` must not enter the expensive relation path;
- the deliberate fixed-probe false-positive must not enter the expensive path; if it does, it is still subject to the 8,192-byte proof ceiling and the normal control CPU gates;
- gate CPU time, actionable-witness CPU time, exact proof/growth + generic emission CPU time, and incumbent CPU time must be reported separately enough to assign cost ownership.

## Disproof / hostile review

INVALIDATE if semantics change, a required novel relation is missed or misidentified, the incumbent internal plan/wire is not preserved, or a pre-gate result is allowed to bypass exact proof.

HOLD if semantics are exact but any frozen density, marginal-yield, proof, state or control-CPU gate fails.

The following are not admissible rehabilitations:

- raising the 1.35x/1.75x control limits;
- weakening the promoted incumbent;
- special-casing benchmark family names or fixed hostile positions;
- treating a pre-gate vote as stored truth;
- hiding the gate or second incumbent call outside timing.
