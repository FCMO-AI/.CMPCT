## Mission lock / referee

The exact native fresh observer has now passed its component transfer gate against the semantically equivalent Python observer. Component speed alone is not sufficient authority for the Genesis creation path: root hashing, relation admission, segmentation, bounded Program construction, full validation and canonical emission can dilute or expose carrying costs.

This experiment asks one narrow system-level question:

> If the only changed stage in the established adjacent-version research-writer envelope is `observe(target)` -> `observe_native(target)`, does the exact native observation transfer survive complete charged writer work without changing Law selection, ONE wire, reconstruction, or resource accounting?

No reader-visible operation, wire format, Law vocabulary, Surprise semantics, comparator, gate workload, or release version changes.

## Frozen arms

For the same `source` and `target` bytes, both arms charge:

1. current-target fresh observation;
2. SHA-256 identity for previous and current roots;
3. the same promoted relation admission;
4. the same native one-pass maximal segmentation when admitted;
5. the same bounded generic Law/Surprise Program construction;
6. the same full validation;
7. the same direct final-buffer canonical emission.

The baseline uses the exact Python `observe()` semantics. The candidate uses the already semantic-proven `observe_native()` implementation. Native compilation/warmup occurs outside timed samples. The ctypes input copy performed by `observe_native()` remains inside every timed candidate call and is therefore charged.

## Semantic gates

Every row must preserve exactly:

- native/Python `Observation`, including stats;
- relation enabled/disabled decision;
- best shift and proof count;
- native segment plan and independent Python plan oracle when applicable;
- canonical ONE bytes and encoding stats;
- decoded `previous` and `current` root bytes;
- reader work/materialization accounting.

Any divergence => `INVALIDATE_NATIVE_OBSERVER_FULL_INGEST`.

## Performance gates

The component authority established native/Python observer CPU ratios from roughly `0.0195x` to `0.0766x`. Prior full-ingest evidence showed fresh observation owning about 98.5–99.1% of the Python-envelope CPU on the tested rows. Therefore a competent transfer should remain a large whole-writer win even after hashing and downstream work are charged.

Frozen gates:

- median candidate/baseline total CPU <= **0.15x**;
- median candidate/baseline total wall <= **0.15x**;
- every row total CPU <= **0.35x**;
- every row total wall <= **0.35x**;
- no row may increase canonical bytes, reader work or reader materialization;
- no new persistent observation state is allowed.

If semantics pass but any performance gate fails => `HOLD_NATIVE_OBSERVER_FULL_INGEST` and localize the stage owner rather than changing thresholds.

All gates pass => `ADVANCE_NATIVE_OBSERVER_FULL_INGEST`.

## Required stage evidence

This benchmark does not claim process peak RSS or hardware-counter DRAM traffic. Those remain separate gate fields.

## Hostile review

A large win is expected from already-observed Amdahl ownership; that expectation is not a license to omit the full writer stages. In particular:

- do not time only the C kernel;
- do not exclude ctypes input copying;
- do not reuse observation outputs across repetitions;
- do not skip root hashes or Program validation;
- do not substitute a friendlier relation case;
- do not execute or preview the September 11 15-workload Genesis score.

A win here promotes the native fresh observer into the **research writer path** only. It does not prove product-native creation, recovery/portability parity, or supremacy over frozen CMPCT comparators.
