## Writer compute convergence

### One-pass native segment-plan construction — advanced

The old relation compiler counted boundaries and then rescanned the target to emit segments. A bounded output allocation makes that count pass unnecessary.

Exact frozen native gate established:

- candidate/baseline/Python-oracle segment plans exact across all rows;
- target scan traffic **0.5x** baseline on every row;
- frozen performance gates passed;
- local corroborating elapsed ratios roughly **0.4948x–0.6448x** over 4–256 KiB;
- no extra persistent state.

At 256 KiB `fragmented_every96`, transient segment-plan state is **65,568 B** (5,464 × 12-byte Segment).

Receipt: `docs/one/evidence/ONE_G02_NATIVE_SEGMENT_PLAN_FUSION_RESULT_2026-09-05.md`.

### Direct control streaming — rejected

Eliminating the transient Segment array and streaming generic controls immediately looked cleaner and reduced transient memory, but repeated evidence made it slower once both alternatives used one input scan. Preserve this negative: the compact Segment plan is useful staging state, not automatically waste.

Do not reopen merely to eliminate the temporary array; reopen only with a causally different native/bulk design that removes its readback cost without recreating incremental-control overhead.

### Post-segment owner localized

A four-stage cost-owner experiment decomposed:

`segment plan -> Program graph -> validation -> canonical byte emission`.

Canonical encode was the dominant post-segment Python boundary (~71.67% median); within encode, actual byte emission dominated validation (~78.54% vs ~21.46%). This prevented a false optimization that might have removed safety validation while calling the gain “serialization”.

Validation remains a hard invariant.

### Pre-sized exact-size emitter — rejected

A one-buffer exact-sizing emitter improved many productive rows but required a complete sizing pass and regressed controls. Its tested shape is retired. Do not rescue it with corpus/size thresholds.

### Growable direct canonical emission — preferred research writer shape

A causally different emitter keeps one-pass growable output but writes uvarints/refs/nodes/blobs directly into the final buffer, avoiding helper-created temporary canonical byte strings.

The isolated emission microbenchmark showed a very large broad gain but one 256 KiB exact-shift row produced a non-reproducible CPython-context red. A dense 96–320 KiB boundary diagnostic did not reproduce a size cliff. The isolated harness therefore remained on hold until a broader writer falsifier could decide whether the mechanism itself survived.

## Current preferred temporal research-writer path

For adjacent versions where pair identity is legitimately available, the currently best evidenced path is:

`root identities -> amortization-safe relation admission -> native one-pass maximal segmentation -> bounded generic Law/Surprise Program -> full validation -> direct final-buffer canonical emission`.

This is a **research-writer path**, not a canonical product writer claim.

The direct-emission optimization changes no stored bytes and no reader semantics; its value is compute efficiency. Its broad gain surviving both the charged relation-to-wire and root-hash-charged envelopes is stronger evidence than the earlier isolated serializer microbenchmarks.

## Current scoped negatives / reopening predicates

Keep these negatives active:

- sparse record-minimum suffix representation: ~99.3% fewer dense suffix writes but 25.35–31.60% slower; do not reopen merely by reducing record count further;
- event-driven dense selection: dramatically fewer nominal recomputes but elapsed regressions; irregular control can cost more than cheap regular comparison;
- single-layer suffix-vs-selection owner ranking is unstable across hosted runs; treat suffix+selection as a co-dominant cluster unless stable material separation is newly proven;
- naive ordinary 8 KiB dispatcher lost the kernel advantage; superseded by tail-return integration;
- direct generic-control streaming from segmentation is slower than plan-then-consume despite lower transient memory;
- exact-size pre-sizing emitter exports an extra pass and is rejected in its tested form;
- isolated growable-emitter 256 KiB anomaly is benchmark/runtime-context debt, not a supported algorithmic size cliff after two broader gates passed that row. Do not invent a 256 KiB threshold.
