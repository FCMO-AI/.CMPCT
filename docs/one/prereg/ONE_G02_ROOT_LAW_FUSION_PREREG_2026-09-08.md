# ONE-G0.2 root Law fusion — preregistration and hostile review

Date: 2026-09-08
Research version: ONE-G0.2

## Mission lock

The relation-granularity frontier proved a density region inside the existing six-op ONE grammar but exposed a severe reader penalty: 1 MiB relation Programs materialize 2.5x the literal bytes, charge 2.333x reference work, and replay 3.26–17.3x slower than literal even with native add8/XOR arithmetic.

The hypothesis is that **generic Law fusion**, already called for by ONE's efficiency law, can remove that implementation penalty without changing the stored Program. The candidate may fuse only execution geometry. No new opcode, changed wire byte, widened node limit, format fallback, reader discovery, weakened root hash, or relation-specific stored primitive is allowed.

## Frozen candidate

Compile the existing prepared Program only when its single full root is a `concat` of:

- full direct `surprise` children; and/or
- full `add8` / `xor` children whose operands are one full `surprise` plus one full uniform `fill`.

The resulting reader-internal schedule contains COPY, XOR-constant and ADD8-constant commands. One bounded native call writes every command directly to its final root position. Fill and relation result buffers are never materialized and the final Concat does not recopy them. SHA-256 over the complete reconstructed root remains inside every timed replay.

Unsupported graphs fail closed. There is no internal fallback.

## Frozen matrix

- sizes: 64 KiB, 256 KiB, 1 MiB;
- relation block sizes: 512 B and 4096 B;
- operations: add8 and XOR;
- 12 exact cells;
- 21 paired rotating hot replays after warmup.

The inputs and existing Programs are generated by the already-preregistered relation-granularity frontier: independent parent blocks, one non-zero transformed child per parent, no aligned duplicate blocks. Wire bytes come from the unchanged `encode_program` result.

## Metrics

For every row preserve:

- exact candidate/literal wire ratio;
- generic native prepared replay wall + CPU;
- fused replay wall + CPU;
- literal prepared replay wall + CPU;
- fused/generic and fused/literal ratios;
- command count;
- modeled memory traffic;
- compile-to-fused-plan cost;
- exact reconstruction and root-hash equality.

The traffic model charges every command source read, every final-root write, and one complete root-authentication read. For the relation layout this is expected to be 3x logical output bytes, equal to a physical literal model of stored-payload read + final write + root-auth read. It intentionally does not pretend CPU-cache hits erase memory work.

## Frozen decision law

`INVALIDATE_ROOT_LAW_FUSION` on matrix incompleteness/duplication, any semantic/root mismatch, changed wire density, unsupported-shape acceptance in hostile tests, or modeled fused traffic >1.05x the 3x-literal traffic model.

`ADVANCE_ROOT_LAW_FUSION` only if all four 1 MiB rows simultaneously satisfy:

- candidate/literal ONE wire <=0.55x;
- fused wall and CPU <=0.50x the current generic native prepared replay; and
- fused wall and CPU <=1.25x the literal prepared replay.

Otherwise `HOLD_ROOT_LAW_FUSION`.

The 1.25x literal bound is a causal rehabilitation boundary, **not** a claim that a 25% slower in-memory decoder is a final speed win. Advance would mean the materialization/Concat geometry was causally responsible for most of the pathological 3–17x deficit and that the relation line is worth a later end-to-end I/O/selective-access gate. Canonical promotion still requires the campaign's broader density/speed/access/resource evidence.

## Hostile reviewer

The most likely way to manufacture a green result is to compare against the slow generic relation path while ignoring literal speed. The explicit literal bound prevents that. Another risk is to call the C schedule a new hidden relation codec; it is not admissible unless the stored graph and wire are byte-identical and the schedule can be derived mechanically from existing generic nodes.

Prepacking the execution schedule outside hot replay is allowed because the already-promoted generic execution plan likewise compiles validation/dependency geometry once; compile cost is still reported. Native library build time is outside replay timing because a product reader would ship compiled, consistent with the established native-bulk evidence rule.
