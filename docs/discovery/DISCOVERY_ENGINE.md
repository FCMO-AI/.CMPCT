# CMPCT Discovery Engine — Continuous Single-Agent Scientific Search

**Status:** normative research operating system for autonomous CMPCT discovery; subordinate to repository authority, release law, frozen evidence boundaries, and hard correctness/safety invariants.

## Purpose

CMPCT already has strong local scientific machinery: frozen gates, mechanism hypotheses, detached oracles, negative evidence, breakthrough rehabilitation, exact product receipts, and a durable repository. What it lacks is a persistent search architecture that makes successive scheduled activations compound rather than repeatedly rediscovering the next question.

This system turns one recurring agent into a serial scientific institution. It is not a swarm, not an LLM self-training loop, and not a second source of project state. The repository remains memory; experiments remain reality; the scheduled activation remains an executor.

The useful recursive idea is to improve the process that chooses and tests discoveries, adapted to CMPCT's real constraints: one agent, short activations, GitHub as durable memory, CI/hosted compute as asynchronous instruments, expensive benchmark evidence, strict anti-Goodhart rules, and an active product convergence frontier.

## PARETOBONK result

A proposal survives only if expected information/product value justifies cost across the whole CMPCT Pareto surface. Never collapse this into one RSI score.

Track a Pareto vector: headroom; causal fit; information gain; generality; product leverage; novelty distance from saturated families; evidence cost; carrying cost; risk; and reversibility.

Repository law supplies hard lexicographic boundaries. Otherwise maintain a nondominated set and choose the candidate with the best value of information per scarce execution resource, biased toward actions that can falsify an entire family.

### BONK filters

Before implementation:

1. Baseline BONK — does current evidence already answer it?
2. Sunk-family BONK — is this a renamed rejected/saturated family without changed evidence?
3. Oracle BONK — can a cheaper generous oracle establish enough headroom?
4. Control BONK — can a simpler control explain the same gain?
5. Exported-cost BONK — where will bytes/work/memory/dependency depth move?
6. Generality BONK — would it survive held-out structural perturbation?
7. Product BONK — if the oracle wins, is there a credible bounded decoder/product path?
8. Opportunity BONK — is this better than repairing the dominant measured product debt?
9. Evidence BONK — can available infrastructure produce a decision-changing result?
10. Complexity BONK — what can be deleted or reused instead?

A candidate killed by a BONK becomes durable negative knowledge when the reason is reusable.

## Four coupled loops

### A — Exploit the measured bottleneck

When exact product evidence exposes a dominant owner, prefer causal localization and the smallest decisive A/B. This is the default while v0.30 runtime debt is release-critical.

Do not optimize wrappers when child attribution points into candidate construction. Do not tune thresholds before determining whether work can be eliminated, reused, bounded, proven unnecessary, or terminated early.

### B — Explore representation headroom

Maintain a small frontier of genuinely different abstractions. Start with generous, fully charged oracles. An oracle gets no product credit, but can prove whether a family has enough ceiling to justify implementation.

Search exact inverse/view relationships, cross-object reconstruction, physical organization, program/grammar descriptions, ownership changes, proof-carrying selection, indexing/access structures, update/recovery structures, and execution architectures—not only codecs.

### C — Rehabilitate breakthroughs

A large verified gain with debt becomes a protected seed. Search for ways to preserve the gain while removing exported cost. Prefer adaptive coexistence, ownership changes, proof shortcuts, shared work, changed boundaries, or counter-mechanisms over tuning the breakthrough away.

### D — Improve the discovery process

After every decisive experiment, ask what the search policy learned: which probes predicted wins; which families exported hidden cost; which oracle-to-product transitions failed; which measurements were too expensive/weak; which causal decompositions found owners quickly; and which negatives prune future search.

Only evidence-backed process lessons modify this operating system or its machine-readable state. It may improve experimental method, never its authority, release thresholds, benchmark semantics, safety rules, or evidence requirements.

## Persistent discovery state

Use docs/discovery/STATE.json as a compact machine-readable index, not a narrative database. It links to current authority, active product bottleneck, one primary experiment, up to three different-family frontier candidates, protected seeds/debt, saturated families/reopening conditions, pending independent jobs, decisive results, next action, and evidence-backed search-process lessons.

Detailed truth remains in PRs, benchmark records, experiment docs, receipts and code. STATE.json links; it does not duplicate.

## Concurrent activations

Scheduled activations may overlap. Follow `docs/discovery/CONCURRENCY_PROTOCOL.md` whenever concurrent agents, PRs, CI, or human work can touch the same discovery surface. In particular, treat `STATE.json` as a staleable cache rather than a lock; preserve causal history append-only; inspect active claims before substantial implementation; and prefer independent, dependency-safe questions over duplicate implementations. Scientific evidence must survive coordination conflicts intact.

## Activation protocol

Every scheduled activation:

1. ORIENT — read repository authority; reconcile branch/PR/CI/evidence; read this document and STATE.json.
2. OBSERVE — identify strongest product loss, unexplained opportunity, pending decisive evidence, and saturated families.
3. PARETOBONK — compare at least: exploit current measured owner; one different-worldview hypothesis; productize/rehabilitate a proven seed; evidence/infrastructure repair only if it blocks decision-changing work.
4. LOCK ONE QUESTION — baseline, mechanism, simpler control, alternative explanation, kill condition, exact evidence.
5. CHEAPEST DECISIVE TEST FIRST — derivation/profiling/bounds, then micro/A-B, then oracle, held-out perturbation, then expensive full-product benchmark. Do not buy a full matrix for a binary local question.
6. EXECUTE — implement/run/dispatch through existing repo, GitHub Actions, local tools, or available compute. Independent jobs leave durable identity/artifacts.
7. ADVERSARIAL CHECK — attack leakage, benchmark identity, exported cost, semantic weakening, resource bounds, alternative explanations.
8. DECIDE — promote, narrow, preserve-as-seed, falsify/retire, or mark ambiguous. Never rescue by moving the gate.
9. COMPOUND — update only decision-changing durable state. If the lane ends and time remains, choose the next nondominated action.
10. HANDOFF — distinguish product evidence, oracle/research evidence, infrastructure evidence, and unmeasured plans.

## Search-budget law

One agent means concurrency through asynchronous instruments, not parallel identities.

- One primary active question at a time, plus one explicitly dependency-diverse backup that is executable without the primary lane's dominant blocker.
- If the primary completes, blocks, dispatches independently, or must wait, switch to the backup when useful rather than turning blocker handling into the activation.
- Up to three additional queued frontier hypotheses, materially different families unless evidence justifies concentration.
- At most one expensive deep experiment for a question before cheap disproof layers are exhausted.
- While CI/compute runs independently, do useful dependency-safe work; never babysit.
- Three consecutive activations on the same blocker/family without decision-changing evidence trigger frame review: materially different route, one bounded final attempt, or retirement/nonblocking debt.
- Optimize infrastructure only when it increases expected scientific throughput across multiple experiments or is required for a live decisive claim.

## Anti-Goodhart / anti-self-deception

The Discovery Engine cannot alter frozen benchmarks, thresholds, comparators, process boundaries, semantics or release gates; treat oracle bytes as product bytes; add savings that cannot coexist in one artifact; encode workload identity/fixture hashes into generic policy; count commits/tests/hypotheses/activations/versions as discovery; rewrite a negative as pending because it disappoints; or modify this system based only on intuition about its own performance.

Success is a changed map of what is possible: product improvement, decisive falsification, newly measured bound, preserved breakthrough with reduced debt, or an evidence-backed search-method lesson that makes future decisions cheaper/better.

## Current bootstrap target — temporal, not permanent doctrine

At creation time, v0.30 convergence evidence identifies runtime rehabilitation as release-critical debt. PR #132 reports shared candidate construction owns most measured G04 creation time on Shifted and ML, with finer v0.28-child vs attempt-5-child attribution pending.

The first cycle should exploit before wandering:

1. reconcile exact-head child attribution;
2. determine which child owns the critical wall;
3. test whether the selected-winner fact can be proven materially cheaper via safe lower bounds, reuse, admission, or early termination;
4. preserve exact selected bytes and frozen product semantics;
5. if the expensive child is fundamentally required, escalate to changed ownership/execution architecture rather than wrapper micro-optimization.

Keep one cheap worldview-distance hypothesis alive so runtime rehabilitation does not become a permanent local optimum. Update/remove this bootstrap section when repository truth changes.

## Completion criterion

The system is operational when a zero-history scheduled activation can recover authority; identify the frontier; select a nondominated question without benchmark identity leakage; execute or durably dispatch the cheapest decisive test; preserve negative/positive evidence; update compact discovery state; continue without waiting; and hand the next activation a decision-complete frontier.

It is never complete in the sense of ending research. Completion means a self-renewing, evidence-governed scientific loop exists.
