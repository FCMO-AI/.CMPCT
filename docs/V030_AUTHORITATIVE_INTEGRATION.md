## Mission lock

The v0.30 campaign has accumulated several orthogonal mechanisms and rehabilitation layers. The release problem is now convergence: retain only mechanisms that survive exact complete-artifact accounting, compose them without double-counting savings, preserve inherited no-regression floors, and close reader/performance/portability debt before promotion.

- exact fallback to accepted v0.29 whenever a v0.30 representation loses;
- complete repaired 15-workload generalization with zero inherited byte regressions;
- exact source-tree identities before savings are credited;
- per-member selective-read amplification <=8x and max decode unit <=8 MiB;

- deterministic golden vectors and native/shared-reader parity for every promoted grammar feature;
- ZIP/export and ordinary portability gates;
- controlled create/extract/selective-read/peak-memory measurements;
- external competitor matrix rerun;
- public site/release claims generated only from durable accepted evidence.

## Non-additivity rule

Independent savings are never summed as a release claim. Every composition step must build a complete archive and compare exact final bytes. Portfolio evidence proves coexistence only; it is not a substitute for a hybrid artifact.

## Current architecture target

`accepted v0.29 floor -> attempt-5 pre-fallback graph -> G0-G4 Geometry physical overlay -> shallow PrefixGraph edge where eligible -> exact complete-artifact tournament -> transactional publication`

The reader must decode the promoted transform/reference set directly; temporary verification views are research adapters only.

If full G0-G4 overlay fails its frozen gates, the fallback architecture is a complete-artifact tournament between accepted v0.29 and standalone GIR, but that path must justify the added grammar/native-reader cost with materially stronger broad-corpus evidence.

## Integration discipline

1. Re-resolve source branch heads before every import because other agents may still be working.
2. Prefer merging orthogonal implementation layers over hand-copying code.
3. Do not modify another agent's evidence branch merely to make integration convenient.
4. Preserve rejected/negative evidence; never overwrite historical JSON with a later substrate.
5. A queued/cancelled Action is not evidence. Only executed gate output on the exact referenced head is authoritative.
6. Promotion waits for the full release matrix; integration may proceed on this branch while research CI runs.
