## Mission lock

The v0.30 campaign has accumulated several orthogonal mechanisms and rehabilitation layers. The release problem is convergence: retain only mechanisms that survive exact complete-artifact accounting, compose them without double-counting savings, preserve inherited no-regression floors, and close reader/performance/portability debt before promotion.

### Required release properties

- exact genuine r24 fallback whenever a canonical r25 product candidate loses or is unsupported;
- complete repaired 15-workload generalization with zero inherited byte regressions;
- exact source-tree identities before savings are credited;
- per-member selective-read amplification <=8x and max decode unit <=8 MiB;
- bounded parser/metadata/materialization behavior and hostile-input rejection;
- streaming/transactional extraction with authenticated tree verification and publication rollback;
- deterministic golden vectors and native/shared-reader parity for every promoted grammar feature;
- ZIP/export and ordinary portability gates;
- controlled create/extract/selective-read/peak-memory measurements;
- external competitor matrix rerun;
- public site/release claims generated only from durable accepted evidence.

## Non-additivity rule

Independent savings are never summed as a release claim. Every composition step must build a complete archive and compare exact final bytes. Portfolio evidence proves coexistence only; it is not a substitute for a hybrid artifact.

## Current architecture target

Preferred path, conditional on exact evidence:

`genuine r24 product floor -> canonical r25 attempt-5/pre-fallback graph -> G0-G4 Geometry -> shallow PrefixGraph edge where eligible -> exact complete-artifact tournament -> transactional publication`

The reader must decode the promoted transform/reference set directly; temporary verification views are research adapters only.

If full G0-G4 composition fails its frozen gates, fallback is genuine r24 publication. A more complex alternate grammar may be retained only as research unless it justifies its reader/native/portability burden with materially stronger broad-system evidence and still passes the product floor.

## Integration discipline

1. Resolve current `main` immediately before reconciliation and record exact SHAs/fingerprints where required.
2. Work directly on the authoritative branch for release implementation; use research branches only for deliberately isolated experiments.
3. Preserve rejected/negative evidence; never overwrite historical JSON with a later substrate.
4. A queued/cancelled Action is not evidence. Only executed gate output tied to the exact candidate is authoritative.
5. Promotion waits for the full release matrix; implementation may continue while non-blocking evidence jobs run.
6. Do not merge to `main` while any normative release gate remains open or the strict release lock is not `UNLOCKED`.
