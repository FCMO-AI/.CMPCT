# CMPCT v0.26.0 — Performance-command-center release

Date: 2026-08-16

Project version: **0.26.0**  
Canonical on-disk format revision: **24 (unchanged)**

## Release objective

Turn performance from a buried benchmark appendix into a release contract and the dominant public story of CMPCT. The website is rebuilt as a live performance command center generated from committed benchmark history, and every material update is required to run a candidate-vs-base performance gate.

## Added

- a substantially redesigned public site with a performance-first hero, live frontier metrics, competitor ladder, workload win/loss matrix, canonical-engine parity view, release trajectory, and Browser Lab;
- site data that understands both canonical ZIP-parity records and EntropyGraph research-frontier records;
- a release performance gate that benchmarks the candidate and its base revision on the same runner and rejects deterministic size regressions;
- noise-aware speed regression checks so CI jitter is not mistaken for a product regression while material slowdowns still fail;
- workflow coverage on pull requests and `main`, rather than a benchmark job stranded on one historical feature branch;
- explicit publication language separating the canonical revision-24 engine from the current EntropyGraph research frontier while still surfacing the strongest verified project-level results.

## Performance policy

A material update may not silently trade away performance. Deterministic archive-size regressions are zero-tolerance on the fixed parity corpus. Speed is measured candidate-vs-base on the same runner and fails when a slowdown exceeds the configured noise envelope. Benchmark losses remain visible; the site does not delete workloads to improve the headline.

The performance workflow also emits a fresh machine-readable candidate record for each update so reviewers can inspect the new version before merge.

## Compatibility

The canonical Python/native reader and writer remain format revision 24. This release changes public presentation, benchmark automation, and release discipline; it does not mutate the on-disk grammar.
