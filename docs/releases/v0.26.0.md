# CMPCT v0.26.0 — Performance-command-center release

Date: 2026-08-16

Project version: **0.26.0**  
Canonical on-disk format revision: **24 (unchanged)**

## Release objective

Turn performance from a buried benchmark appendix into a release contract and the dominant public story of CMPCT. The website is rebuilt as a live performance command center generated from committed benchmark history, and every material update is required to run a candidate-vs-base performance gate.

## Added

- a substantially redesigned public site with a performance-first hero, live frontier metrics, competitor ladder, workload win/loss matrix, canonical-engine parity view, release trajectory, information-graph visualization and Browser Lab;
- site data that understands both canonical ZIP-parity records and EntropyGraph research-frontier records;
- a release performance gate that benchmarks the candidate and its direct base on the same runner and rejects deterministic size regressions;
- a deterministic canonical benchmark generator and one-tree base/candidate comparison so corpus randomness or timestamps cannot manufacture a byte win/loss;
- symmetric ABBA timing order (`base → candidate → candidate → base`) so first/second-runner drift is controlled without weakening the speed requirement;
- noise-aware speed regression checks so shared-runner jitter is not mistaken for a product regression while confirmed material slowdowns still fail;
- machine enforcement that every material project version adds a fresh `benchmarks/history/*.json` record with the matching `project_version`;
- workflow coverage on pull requests and `main`, rather than a benchmark job stranded on one historical feature branch;
- explicit publication language separating the canonical revision-24 engine from the EntropyGraph research frontier while still surfacing the strongest verified project-level results.

## Performance policy

A material update may not silently trade away performance. Deterministic archive-size regressions are zero-tolerance on the release parity corpus. Speed is measured candidate-vs-base on the same runner and fails when a slowdown exceeds both sides of the configured confidence envelope. Benchmark losses remain visible; the site does not delete workloads to improve the headline.

CI artifacts are diagnostic. The accepted machine-readable result must also be committed under `benchmarks/history/`, where the site and future agents can consume it without depending on an expiring workflow artifact.

## Compatibility

The canonical Python/native reader and writer remain format revision 24. This release changes public presentation, benchmark automation and release discipline; it does not mutate the on-disk grammar.
