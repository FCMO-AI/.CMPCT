# CMPCT v0.29.0 — Mosaic / Residual Program Packing

Project version: **0.29.0**

Canonical on-disk format: **revision 24 (unchanged)**

Surface revision: **0.29.a**

## Why this release earns a core number

v0.29.0 advances CMPCT's verified research frontier without pretending the experimental bytes are already
canonical. Accepted attempt #5 combines bounded multi-root Mosaic Placement, Residual Program Packing,
and exact v0.28 fallback. It cleared the complete-artifact hostile gate, generalized without a single
size regression across the inherited 15-workload frontier, and gained a byte-identical scheduler path
that removes a material portion of its creation-wall-time penalty on the fixed hostile aggregate.

The canonical Python/native reader-writer remains revision 24. The research grammar is `CMPNX11`; it is
not emitted by `python -m cmpct create` and must not be presented as revision-24 syntax.

## Creation-time correction

The first scheduler experiment was invalid for release purposes even though its timing math was real:
it accidentally scheduled the obsolete attempt-1 `CMPNX9` portfolio and selected the exact v0.28 fallback
(**47,197,165 B**) rather than accepted attempt #5 (**47,147,764 B**). Its durable evidence has been
explicitly invalidated instead of deleted.

The corrected scheduler pins `accepted_engine=attempt5-residual-program-packing`, requires exact
byte-for-byte equality with the accepted sequential attempt-5 wrapper, preserves the single-file
fast-reject policy, and uses four balanced ABBA paired repetitions. Every pair and the median must save
at least **20% and 5 seconds** on the fixed hostile aggregate.

On that gate:

- sequential median: **182.454 s**
- parallel release scheduler median: **97.944 s**
- median wall time saved: **84.510 s**
- median improvement: **46.318%**
- every paired repetition: **PASS** (each cleared both ≥20% and ≥5 s)
- selected archive every repetition: **47,147,764 B**
- embedded v0.28 fallback: **47,197,165 B**
- selected archive SHA-256: **`9e1d587a15e5499e4b9e7f8352d33f014fdfcb55a18339884942e7887b56d376`**
- exact sequential/parallel archive identity: **PASS**
- corrected workflow run: **32049354204**
- durable workflow artifact: **9294641438**

The scheduler speed result is deliberately scoped to that fixed multi-file hostile aggregate. It is not a
global creation-speed claim. Single-file inputs retain the accepted sequential fast-reject policy rather
than speculatively launching an expensive research branch.

Footnote: the scheduler result does not erase the portable generalization record's historical **2.175x**
attempt-5/v0.28 creation ratio or imply the same speedup on every workload.

## What was rejected

v0.29 is also defined by mechanisms we measured and did **not** ship:

- shared dictionary record context — below its frozen materiality gate;
- one-hop reference context — no archive saving;
- bounded per-record LZMA2 backend — only a tiny byte reduction, below the gate;
- bounded solid LZMA2 — no saving;
- local pair fusion — no saving;
- attempt #6 locality-budget compiler — no additional hostile structural saving;
- attempt #7 cross-base residual packing — only **1,303 B** beyond attempt #5 and still **83,822 B**
  larger than same-run ZPAQ;
- reversible columnar residual representation — all measured residual groups became larger.

This rejection ledger matters: v0.29 is a measured frontier, not a pile of dormant complexity.

## Compatibility and canonicality

- canonical format magic/revision stays **r24**;
- canonical Python/native readers and Browser Lab r24 writer remain unchanged;
- `CMPNX11` is experimental and is not accepted by the canonical r24 reader;
- Mosaic logical dependency depth remains bounded and residual records retain their locality/resource caps;
- public evidence contains only deterministic synthetic/public benchmark material;
- the website presents the v0.29 research frontier separately from canonical ZIP parity.

## Release boundary

This release advances the **project/research engine**, not the on-disk canonical grammar. A future
format revision must separately earn reader integration, conformance, malformed/resource tests, native
parity, recovery semantics, portability, and direct-base canonical performance evidence.

therefore a legitimate material research-engine milestone while canonical archives remain revision 24.
