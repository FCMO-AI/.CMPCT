## Release objective

Correct the zero-chat-history handoff after v0.27.0 so a future contributor receives one coherent
canonical account of the project rather than seeing `pyproject.toml`/the newest release say v0.27 while
`docs/CURRENT_STATE.md` still identifies v0.26 as current.

This is intentionally versioned instead of being hidden as a “tiny docs fix.” `docs/CURRENT_STATE.md`
is now a material policy/handoff surface under version discipline because incorrect canonical context
can alter future engineering behavior even when archive bytes are unchanged.

## Preservation check

The existing handoff was not replaced from scratch. Its canonical architecture descriptions, revision-24
capabilities, EntropyGraph frontier, benchmark semantics, open production gaps, seven high-value missions,
historical traps and format-revision rules were preserved. The patch changes the stale authority layer
and adds the v0.27 engineering contract around it.

Footnote: this patch exists because the v0.27 adversarial verification caught the stale handoff after
merge. That negative finding is itself part of the quality-ratchet behavior: when the repository exposes
an inconsistency, correct the root canonical context rather than explaining the inconsistency away.
