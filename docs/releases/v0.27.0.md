# CMPCT v0.27.0 — AGI-grade engineering standard

Date: 2026-08-16

Project version: **0.27.0**  
Canonical on-disk format revision: **24 (unchanged)**

## Release objective

Make exceptional, evidence-grounded engineering the default operating contract for every future
material CMPCT task.

“AGI-grade” is deliberately defined as an engineering-quality shorthand, not as a claim that any
contributor, model or tool possesses AGI. In CMPCT it means unusually strong systems reasoning,
falsifiable hypotheses, adversarial skepticism, broad technical synthesis, independent evidence and
measurable frontier movement that remains convincing under hostile review.

This milestone changes the repository's engineering constitution and review discipline. It does not
change canonical revision-24 archive bytes or reader semantics.

## Added

- `docs/AGI_ENGINEERING_STANDARD.md`, a normative quality-ratchet and invention protocol for material
  engineering work;
- an explicit evidence hierarchy that prefers independent byte oracles, deterministic experiments and
  direct-base measurements over intuition or prose;
- a pre-implementation problem-framing contract: baseline, invariant, constraint map, hypothesis,
  disproof test and acceptance evidence;
- an invention pass that asks engineers to model the real cost, eliminate avoidable work, reuse existing
  representations, consider multiple solution classes and search adjacent technical fields when useful;
- an adversarial self-review protocol covering hostile inputs, pathological workloads, resource bounds,
  selective-read amplification, integrity, recovery, path semantics, optional dependencies and
  portability assumptions;
- explicit complexity accounting across archive bytes, CPU/time, peak memory, bytes touched/decoded,
  dependency depth, integrity/recovery work, temporary materialization, reader complexity and portability;
- a research-to-production promotion bar requiring precise semantics, reproducible benefit, known losses,
  independent conformance, bounded resource behavior, hostile testing and compatibility planning;
- `.github/PULL_REQUEST_TEMPLATE.md`, which turns the material-PR completion dossier into a visible,
  falsifiable review surface instead of a generic checklist.

## Strengthened repository enforcement

`AGENTS.md` now makes the AGI-grade engineering standard mandatory before material development and
requires the quality ratchet, multiple-solution/invention reasoning where appropriate, disproof tests,
adversarial review, explicit losses and a completion dossier.

`tools/check_version_discipline.py` now treats the engineering constitution, PR evidence contract and
canonical handoff/research/benchmark policy documents as material surfaces. Future changes to the rules
agents inherit cannot quietly bypass project versioning merely because they are documentation changes.

Footnote: machine checks cannot prove creativity or insight. The repository therefore automates the
parts that *are* objectively enforceable—versioning, durable benchmark evidence, performance
non-regression and publication coherence—while the engineering standard makes the reasoning/evidence
bar explicit enough for agents and reviewers to falsify weak work.

## Quality-ratchet contract

Every material milestone must preserve inherited verified strengths while improving at least one
meaningful dimension or producing a durable negative result that prevents future wasted work.

A material PR is not complete merely because tests are green. It must make clear:

1. what problem/opportunity and baseline were observed;
2. what mechanism is expected to improve the system;
3. what practical result would disprove that explanation;
4. what meaningful alternatives were considered;
5. what independent tests, oracles and benchmark records support the result;
6. what losses, ambiguities and competitor wins remain;
7. what safety, resource, integrity, recovery and compatibility boundaries were exercised;
8. what became measurably better without silently exporting cost elsewhere;
9. what future capability or high-value defect the work exposes.

## Performance contract

The performance contract is not relaxed for process/documentation releases. Even governance work must
prove it did not move the executable frontier backward. Deterministic archive-size growth remains
zero-tolerance, and timing uses the same-runner ABBA/noise policy defined by
`docs/PERFORMANCE_RELEASE_GATE.md`.
