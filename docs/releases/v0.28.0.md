# CMPCT v0.28.0 — EntropyGraph II resemblance frontier

Date: 2026-08-16

Project version: **0.28.0**  
Canonical on-disk format revision: **24 (unchanged)**  
Research grammar: **CMPNX8 when EntropyGraph II wins; exact inherited CMPNX5 fallback otherwise**

## Release objective

v0.28.0 promotes the **EntropyGraph II / Resemblance Compiler** campaign to a scarce project-version
milestone because the fixed public research suite demonstrates a large, reproducible reduction in
stored bytes without hiding losing workloads or weakening the locality contract.

This release does **not** claim that ordinary revision-24 `cmpct create` output now uses CMPNX8 graph
storage. Project version and on-disk format revision are independent. Canonical reader-visible graph
promotion remains gated on a future format revision with independent vectors, hostile parser/resource
coverage, native parity, recovery rules and portability/export semantics.

## What materially changed

- deterministic FastCDC-style bounded resemblance units;
- bounded multi-band similarity discovery instead of all-pairs comparison;
- measured COPY/LITERAL deltas with **maximum dependency depth 1**;
- central-base selection that prevents delta-on-delta chains;
- similarity-ordered physical roots with adaptive 64 KiB–2 MiB packing;
- an explicit **8x weighted read-amplification ceiling** for admitted pack plans;
- an optional pinned, memory-safe preflate bridge for exact DEFLATE-bearing transformations;
- Merkle-authenticated physical payload leaves plus SHA-256/CRC reconstruction checks;
- authenticated redundant metadata with exercised tail recovery;
- a strict portfolio rule that emits the inherited v0.25 artifact unchanged whenever the new graph is
  not smaller;
- deterministic parallel canonical creation plus strict remote-range/fuzz/resource validation from the
  finalized systems tranche.

Footnote: the portfolio deliberately spends extra encoder CPU to measure competing representations.
That cost remains visible in the benchmark record; the release does not pretend candidate audition is
free merely because stored bytes improve.

## Accepted research evidence

The durable public record is:

`benchmarks/history/2026-08-16-entropygraph-v028.json`

It retains all 15 workload rows, tree fingerprints, inherited/candidate/raw-graph sizes, selection
outcomes, creation and strong-verification costs, bounded graph/locality statistics, both structural
competitor aggregates, and the SHA-256 of the full raw CI artifact from which it was accepted.

Across the fixed neutral + resemblance-hostile research workloads:

- inherited v0.25: **166,816,028 bytes**;
- v0.28 portfolio candidate: **137,557,457 bytes**;
- reduction versus inherited v0.25: **17.5394%**;
- workloads improved: **3**;
- workloads regressed: **0**;
- selected resemblance workloads: **3**;
- measured delta nodes: **233**;
- exact preflate wins: **25**.

The large wins are concentrated where the mechanism predicts they should exist rather than smeared
across an average:

- shifted near-duplicate versions: **30,200,827 → 1,761,588 bytes (-94.17%)**;
- repeated boundary churn: **866,651 → 89,945 bytes (-89.62%)**;
- ML-artifact workload: **13,879,065 → 13,836,439 bytes (-0.31%)**.

Every other fixed workload retains the inherited v0.25 artifact exactly when EntropyGraph II does not
win. This is the release's no-size-regression mechanism, not a post-hoc average threshold.

## Structural competitor context

On the resemblance-hostile aggregate, the selected CMPCT research candidate stores **47,197,165
bytes**, placing it in the same size class as solid tar+Zstd-19 (**47,065,652**), 7z/LZMA2
(**47,430,344**) and ZPAQ method 5 (**47,062,641**) while remaining far below ZIP/Deflate-9
(**76,690,799**). Those tools do not provide identical random-member/recovery semantics, so this
release preserves their semantic differences instead of collapsing unlike operational contracts into
a fake scalar winner.

On the neutral/hostile aggregate, inherited v0.25 remains the selected portfolio representation where it
is better. Losing workloads and unavailable competitors remain recorded.

## Reliability and locality contract

The finalized tranche additionally proves:

- single-worker and multi-worker canonical creation are byte-identical in reproducible mode;
- strict HTTP/range reads cannot silently fetch the whole archive;
- malformed graph/delta inputs are bounded and fuzzed;
- graph dependencies are depth-1 only;
- physical decode units and decoder working-memory ceilings are explicit;
- primary metadata damage recovers through the authenticated tail copy;
- physical payload corruption is detected without weakening unrelated metadata recovery.

## Compatibility

Canonical Python/native reader and writer semantics remain **revision 24**. `src/cmpct/__init__.py`
therefore continues to identify the current on-disk prototype revision rather than mirroring the
project release number. No existing revision-24 reader is asked to interpret CMPNX8 bytes.

The next reader-visible promotion must earn a new format revision; it is not implied by v0.28.0.

## Promotion boundary

v0.28.0 means the EntropyGraph II mechanism has earned durable project status and a public benchmark
record. It does **not** mean every experimental transform is automatically enabled in the canonical
writer. Canonical promotion remains representation-by-representation and requires the stricter
research-to-production checklist in `docs/AGI_ENGINEERING_STANDARD.md`.
