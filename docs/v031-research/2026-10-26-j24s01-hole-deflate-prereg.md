# J24S01 sparse-hole DEFLATE research preregistration
Date: 2026-10-26 UTC. Frozen before experiments. Source base O193 PR #521 at 392112ce859db5a7f85be593c82d1cabc1f5131f. Released v0.30.0/r24 unchanged.

Question: On generically identified and validated S_SPARSE zero extents, can concatenated independent byte-aligned Z_SYNC_FLUSH raw-DEFLATE zero-block templates reduce ZIP-compatible encoding CPU without sacrificing decoded bytes, SHA256, CRC32, output size or bounded memory? Investigate an offline research oracle only; no product edits.

A strong baseline is ordinary raw zlib compression of every 1MiB block at levels 1 and 6. A stronger framing control flushes every 1MiB but still compresses zero blocks. The candidate precomputes a one-MiB zero fragment from a fresh compressor, copies the nonfinal compressed fragment at eligible holes, compresses nonzero data separately, and ends the joined stream with an empty final raw-DEFLATE block. Both paths must compute the same incremental SHA256 and CRC32 over every logical byte. Reader correctness uses an independent streaming raw-DEFLATE decoder, exact logical SHA/CRC, eof and no trailing data.

Fixed workloads: 256MiB all-zero 1MiB sparse extents, 256MiB mixed sixteen-MiB periods each containing 4KiB deterministic data and otherwise sparse zeros, and 64MiB nonhole incompressible fallback. At least three interleaved paired repetitions, raw CPU/wall, full payload bytes, output hashes, RSS, compressor calls and decoder checks. Predicted candidate >1.5x faster fully SHA/CRC charged on all-zero and <=5 percent extra compressed bytes. If below that, retire fixed-template optimization. If mixed case incurs >10 percent extra size, narrow to positive-only byte admission. Any decoder error or differing hashes invalidates the claim.

O195 PR #524 observed only 4.2253 percent complete 4GiB sparse export wall improvement from a bisect metadata index (below prereg threshold); this tests a different representation/execution dimension. ZIP64 validity, installed CMPCT, Windows/macOS, general runtime and release gates are unmeasured and receive zero product credit. No O193/O195 owner source or discovery state will be overwritten. Standards: RFC1951 and zlib Z_SYNC_FLUSH specification. Preserve this prediction unchanged; write outcomes separately.
