# O52b — parent-component escape vs final-only O_NOFOLLOW (secondary lower-rung prereg, 2026-10-25 UTC)

**Relationship to O52:** The primary genuine O50 Builder post-stat pivot result is already scientifically complete on [PR #407](https://github.com/FCMO-AI/.CMPCT/pull/407), Actions #40160804316. This separate *primitive-only* follow-up is not another product implementation and does not change the O52 original source/executed experiments. It prunes a dangerous but tempting proposed fix: nofollow only on the final regular-file component.

## Prior evidence already observed (not a preregistered new discovery)
Before this document, a local Linux exploratory stdlib script created `src/child/file.bin` and a distinct external parent containing `file.bin`, renamed `src/child`, and inserted `src/child` as a symlink to the external directory. A final-component `os.open(src/child/file.bin, O_RDONLY|O_NONBLOCK|O_NOFOLLOW)` returned **external bytes**. Opening `child` relative to an already-open trusted source directory fd using `O_DIRECTORY|O_NOFOLLOW` raised `NotADirectoryError(errno=20)`; reading via an already-open original child directory fd returned **original bytes**. This is a single-host lower-rung exploratory observation, not independently hosted proof or CMPCT product behavior.

## Question and prospective hosted claim
Across hosted Linux/macOS with CPython 3.11, does the POSIX same-input path experiment reproduce three discriminating results? (A) final-only `O_NOFOLLOW` still traverses an *ancestor* symlink and obtains external bytes; (B) descriptor-relative opening of the ancestor with `O_DIRECTORY|O_NOFOLLOW` refuses the pivot; (C) an already-pinned child-dir fd continues to reference the original directory inode despite pathname replacement. Stable explicit regular file reading must succeed before pivot. On Windows report test skipped as out-of-scope; no portable protection credited.

## Controls / evidence
Create actual independent files under a temp tree with **different known contents** and use real Python `os.open`, `os.fdopen`, `os.symlink`, `os.rename`, `os.fstat`. Do not use CMPCT or a mock/monkeypatch for this primitive. Source file test should require host platform support for `os.supports_dir_fd`, `O_NOFOLLOW`, `O_DIRECTORY`. Expect `ELOOP` or `ENOTDIR` from the anchored child-path rejection, not a specific OS exception type. Record both open modes' observed byte identities in test output/JUnit. Require an actual hosted JUnit PASS for POSIX and explicit Windows skipped. Fail the court if the source path is unchanged or a test is silently omitted.

## Disproof / product boundary
Any POSIX host where final-only `O_NOFOLLOW` rejects the ancestor pivot, or an anchored directory-walk follows the symlink unexpectedly, or already-pinned fd returns external bytes, narrows/rejects transfer. These are direct kernel/Python primitive tests: **they neither prove a production Builder repair nor establish complete containment** (e.g. traversals, network FS, devices, inode mutation, Windows). No format, Builder, Writer, Reader, release, research matrix or gate changes. No policy update from one corroborating experiment. Nontrivial productized follow-up requires source root ownership and path-component/descriptor handling across all Builder pathways and race tests, not only final file nofollow.
