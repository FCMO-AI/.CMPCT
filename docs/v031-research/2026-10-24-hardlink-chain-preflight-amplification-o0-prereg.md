## Baseline and causal hypothesis
Strict preflight iterates every hardlink alias, allocating a fresh `walked` set and walking target pointers until a regular owner. An acyclic chain of N aliases causes 1+2+…+N = N(N+1)/2 traversals; N independent aliases all targeting the same owner need O(N) traversals. `ParserLimits.max_files=4,000,000` caps *entries*, not resulting traversals. A cheap structurally valid malicious index may consume disproportionate CPU even without payload decompression. The key invariant is every alias must terminate at a valid regular-file owner without cycles.

## Cheapest decisive O0
Generate authentic revision-24 Builder archives with **one** physical owner and N logically authenticated hardlink aliases using the same physical blob bytes; re-sign both index copies and footer. Create same-size `chain` and `star` families at N=128, 512, 2048 (if practical 4096), with same fixed-width path spelling. Verify `preflight_archive` accepts both and reports N+1 files. Report raw monotonic timings and wall/RSS when practical on the **same machine and HEAD**, excluding Builder generation from measured preflight. A separate pure pointer traversal count must match N(N+1)/2 and N, respectively. Output artifact with HEAD, corpus SHA, variants, repetitions, platform. Timing is an O0 research oracle, not a release benchmark.

**Prediction**: on the unmodified parent, chain validation growth is superlinear and the chain/star time ratio increases with N; a profiler or source-bound loop count should attribute the amplification to repeated alias resolution. O0 is falsified or narrowed if full product time is flat, parser overhead dominates, or a stronger existing memo mechanism already bounds traversals. The simpler control is to memoize verified terminal owner identities during the same existing validation and retain cycle/rejection semantics. Alternative: bound the number of aliases/chain depth (safety but excludes legitimate deep graphs), or compress all aliases to direct owners on rewrite (changes archive/writer semantics). No threshold relaxation or filename-tuning.
