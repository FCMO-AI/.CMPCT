## Scientific mechanism and strongest self-critique
Pinning an open stage directory FD and writing/validating the archive through one held file FD prevents many ancestor-rebind attacks; **it does not turn the later source *name* of `renameat` into the verified inode**. The branch therefore has a clear failure in the stronger same-UID stage-leaf adversary model. This does not prove arbitrary cross-UID exploitation. Mode-0700 does normally prevent a separate UID from traversing the private stage directory; a same-UID actor shares DAC credentials, so the threat boundary must be explicit. The deterministic publication interposition proves a feasible schedule, **not the probability or timing of winning a real race**. Neither Windows HANDLE publication nor durability nor power-loss recovery has been studied.

A separate local Linux kernel primitive probe showed `O_TMPFILE` + `linkat(AT_EMPTY_PATH)` can publish an unnamed verified FD at an *absent* destination (matching dev/inode), but fails with `EEXIST` when replacing an existing destination. This is **OS-level research only**, not a portable atomic-replace product solution.
