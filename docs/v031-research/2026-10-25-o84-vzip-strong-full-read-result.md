## Problem and hypothesis
Scientific O81 PR #438, source-exact Linux hosted [40193188582](https://github.com/FCMO-AI/.CMPCT/actions/runs/40193188582) and [40193185335](https://github.com/FCMO-AI/.CMPCT/actions/runs/40193185335), established that the Python ordinary VZIP `read()` does not perform recipe SHA checks and can return physically corrupted same-CRC32 bytes. ## Strongest negative / limits
Ordinary Python `read()` remains CRC-tier **by design**; no claimed fix to all read APIs, VZIP `read_range()`, or arbitrary storage. Opt-in 64 MiB limits *logical SHA scan size*, not all adversarial recipe intermediate work; generic r24 shape, memory, resource, and signed-index hardening remain. The hash prevents corruption relative to the indexed SHA, **not origin forgery when adversary controls index, nor concurrent mutable-archive snapshot races**. Neither a successful hosted scientific court nor an administrative performance workflow meets r24 official full parity/release gate. The measured 25–37× warm-cache cost is substantial and requires explicit opt-in disclosure.
