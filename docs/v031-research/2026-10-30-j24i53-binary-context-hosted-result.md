Both independently reversed treatment groups show prefix-conditioned wall+CPU cost in the same positive direction. This passes preregistered `>5% and >3ms` wall+CPU threshold while the A/A sham does not. The faster/neutral native-only codec court J24I52 does not contradict it: that court excluded Builder, source scanning and the operation prefix.

**Important timing meaning:** process CPU exceeds wall for individual observations because Builder uses concurrent native execution; they are different instruments, not physically impossible results. The active treatment changes more than Python globals: prior Builder operations can affect OS page cache, allocator, module import state, CPU frequency/temperature and thread pool. Therefore `CONTEXT_COST_SUPPORTED` denotes a reproducible *conditioned-run effect in this one hosted experiment*, not proven internal mutable global ownership or a causal base-vs-candidate defect.
