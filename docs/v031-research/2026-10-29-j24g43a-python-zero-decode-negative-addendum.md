# J24G43a — prospective prediction contradicted by real Python: zero-size Zstd decode is skipped

**Chronology:** original scientific prediction [`632c237`](https://github.com/FCMO-AI/.CMPCT/commit/632c237b9e5e0b7602e0a7d31b9312f674e92012) preceded the instrument, and remains unchanged. Initial exact-head hosted [Actions #40882402234](https://github.com/FCMO-AI/.CMPCT/actions/runs/40882402234), source `c01c5b3a7c3b986f07afb0d1b1e6cfcabcdc4e28`, **FAILED on both Ubuntu and macOS** because the original prediction that Python would reject the invalid encoded Zstd frame was **falsified**, not because of infrastructure. Actual Python `CMPCT.verify()`: authentic RAW 1/1; derived valid Zstd-empty 1/1; derived **corrupt Zstd-empty also 1/1**. Source and derived archive SHA-256s matched across both hosts. Raw CI artifacts: Ubuntu #12901585291, macOS #12900438265.

**Causal source audit after observing red:** `src/cmpct/native_codec.py` `decompress(data, usize)` immediately returns `b''` when `usize==0` before reading any encoded bytes; `decompress_using_dict` and `DictDecoder.decompress` have the same early exit. `src/cmpct/reader.py` `_blob()` calls `zd(comp,rus)`, then validates CRC32/SHA of the decoded **empty** bytes; this cannot detect an invalid **nonempty encoded** frame because decompression was bypassed. The compiled Rust verifier in #759 is still predicted to have the parallel zero-size skip `while offset < entry.size`, but this must be measured, not assumed.

**Frozen scoped revision (before second CI), preserving original negative:** Retain authentic Builder source, valid Zstd-empty derived control, **exact same one-byte malformed Zstd physical-frame mutation**, unchanged authenticated index/footer/header/logical CRC/SHA and independent Zstd decoder. Update the test instrument so Python accepting invalid encoded frame is an *expected negative*, not a stop condition. Run the detached parser first to prove encoded corruption and then the compiled native #759 core. The final claim, if corroborated, is **a physical-encoding validity gap in strong verification shared by Python and native**, not differing logical decoded bytes or defeated SHA-256. No attack/exploit or general damaged-archive recovery claim.

**Tradeoff / release:** Native #759 and published main Python sources are both relevant. A fix must distinguish legitimate historical direct zero-byte RAW (no encoded bytes) from nonempty Zstd/other compressed representation, admit only valid physical frames, preserve exact legacy semantics and bounded resource costs. A post-hoc test expectation change is auditable because this addendum explicitly precedes instrument adjustment. No evaluator, threshold, normative policy, release or frozen benchmark is modified.
