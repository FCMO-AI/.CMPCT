# O215 prediction correction — source inspection before experimental observations

2026-10-27 UTC. Original preregistration commit `c5a1acd71db3f37972caa46f83563ceee916f0c7` is immutable and contains a **mistaken specific prediction**: parent `verify()` was expected to accept an S_CHUNKS logical-size mismatch. After reading exact O214 parent `src/cmpct/reader.py`, lines in `CMPCT.read()` confirm `if len(raw)!=size or sha(raw)!=bytes(h): raise IOError`. `verify()` invokes full-read integrity and therefore SHOULD reject a declared-size mismatch. The parent `read_range()` for S_CHUNKS, however, uses the declared `size` for range admission and the physical blob sum for iteration. When `size=5`, blob `ABCD` has four bytes, and `read_range(4,1)` is in-bounds but returns `b''` without an error.

**Corrected falsifiable prediction before testing:** ordinary Reader opens valid-root-version authenticated `S_CHUNKS` with size=5; `read()`/ `verify()` fail, strict preflight fails, yet a direct selective `read_range(4,1)` returns the wrong number of bytes without error. This is a *selective-read admission inconsistency*, not a proven post-verification inconsistency like O198/O201. If baseline does not behave this way, retire the candidate. The closest positive remains declared size 4, which must preserve all byte-exact operations. Narrow type-specific reuse of `_validate_storage` remains proposed only if it changes the admission result and passes frozen positive conformance.

This correction was derived by source inspection, not experimental outcome. It narrows any future product claim and must not erase the earlier mistaken prediction.
