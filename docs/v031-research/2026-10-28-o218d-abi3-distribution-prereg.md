**Status: preregistration only, before implementation or hosted measurement.** Research-only child of O218c #628 exact source \`a2d69c89769868fe4a454ce0556f6a19806f0647\`; no changes to Reader, validator, frozen tests, C source owner, format, release or shared discovery state.

## Material question and baseline
O218c three-host #40607917242 PASS reproduced the unchanged exact-list native scanner on CPython 3.11, with safe-O216/native Reader gains of 3.328–4.706× on the main 65k/262k reference profiles. But C's PyList_GET_ITEM/PyList_GET_SIZE are not permitted by the limited API. Product distribution requires Python minor-version binary handling; compiling at user install time costs 0.396–9.347 s in O218c and requires C toolchains. A standalone reusable \`cp311-abi3\` wheel is a materially different delivery boundary, but requires replacing fast unchecked list macros with bounded stable-ABI calls. A preliminary **local CPython3.13-only, non-Reader micro oracle** found limited-API access ~1.77–1.84× slower than direct macros, so there is uncertainty whether wheel value survives. This observation generated the question; it is not prospective result credit.

## Preregistered prediction
The **unchanged strict predicate** written against \`Py_LIMITED_API=0x030B0000\` can be built as one \`cp311-abi3\` extension wheel per OS on CPython 3.11, then installed and imported **without recompilation** under CPython 3.13, on Ubuntu 24.04, macOS 14 and Windows Server 2022. Native acceptance must match an independent exact-Python predicate on 5,000 fixed-seed adversarial valid/invalid cases on **both minors** and all three hosts, including bool/list subclasses, negative/oversized indices and lengths, overflows and alias-size mismatches. The whole-scan micro median must be at least 1.5× faster than that strict Python predicate at both 65,536 and 262,144 references under identical in-process inputs on **each** OS/minor. Each wheel must advertise \`cp311-abi3\`, contain one extension, and be <=250,000 bytes. Host build wall must be <60 s. These are prospective binary/research thresholds, not release thresholds.

## Strong control, alternative, kill and evidence
Strong simpler control: keep pure Python safe O216 (no native distribution); strongest performance control: original O218 C exact-list macro scanner, already source-locked, but **not** ABI-stable as written. Alternative: per-minor native wheels with higher performance but larger build/support matrix; Rust core if signed journal semantics become equivalent. The cheapest decision rung is source-bound actual bdist_wheel and source-exact wheel reuse across two Python minors on each host; no need for a product merge or full 15-row benchmark. Failing any OS, minor, semantic case, pinned source, wheel tag, minimum micro speed or resource ceiling **kills this wheel path as tested**; no skipped hosts, comparator degradation or threshold gardening. If successful, it licenses **only** the next full-Reader CPython multi-minor ABBA and product-packaging assessment.
