# J24C02b — prospective whole-Reader cold-open cost of same-index S_CHUNKS validation

**2026-10-27 UTC, BEFORE cost-instrument implementation or measurement.** Extends J24C02 #569, not a release gate change. Existing J24C02 exact-head 3-host semantic result was obtained first, so this is a **separate prospective performance question**, not a reinterpretation of the completed correctness court.

## Question and expected mechanism
The strict S_CHUNKS addition loops over every referenced physical blob during ordinary Reader open before mmap, while source-equivalent J24C01 #567 does not. Because refs can repeat one physical blob thousands of times, the cost is O(reference count) instead of logical bytes. How much open wall/CPU and peak RSS is exported on structurally valid independently built r24 fixed-chunk members? Is the extra scan material relative to authentic index parse/mmap cost for 1, 4,096, 65,536 and 262,144 references?

## Exact controls
Baseline is source-exact J24C01 `d3b12852511095d6e98803f55cfd700b8e9ac6b3`, candidate J24C02 current Reader from PR #569 (only O215 constructor differs); both installed as real Python packages in independent locations on same Linux 24.04 runner. Generate each valid archive **once** from the frozen O215 builder-independent wire helper; both arms open the exact same file bytes and source SHA. Keep warm in-process Reader-open micro times separate from subprocess startup; run five opens per process, three ABBA cycles of isolated processes and retain all raw timings. Record index/ref/logical/archive sizes, wall, process CPU and Linux peak RSS separately. Ref count changes workload structure by design; compare **within** each size only. Other Python parsing, module imports and page cache warmups can confound; ABBA/repetition limits but does not erase that uncertainty.

## Prediction / falsifier / decision
Predict monotonic added CPU roughly proportional to refs and potentially substantial overhead by 262,144; no guarantee of the magnitude. Simpler control is original Reader doing identical authenticated root/index parse without extra S_CHUNKS traversal. If candidate/base median ≥2× **and** +5 ms on 65,536 refs or +20 ms on 262,144, mark **material cold-open debt** blocking unqualified product promotion. A smaller signal narrows measured risk but cannot prove no workload-level regression. Any archive invalid for either Reader, mismatched installed Reader identities or input SHA invalidates the run. Never adjust comparison thresholds of normative release gate, alter archive size or hide a negative. Generated bytes are fixture-neutral S_CHUNKS geometry; no corpus identity-specific policy.
