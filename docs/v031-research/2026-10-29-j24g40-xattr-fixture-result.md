## Scientific decision

The initial competing hypothesis “the Linux-style `user.*` key simply needs a macOS namespace substitution” is **falsified as a complete explanation**: the actual Python runtime has no `os.setxattr`, `os.listxattr` or `os.getxattr`. The more fundamental limitation is an OS-native metadata provider boundary, despite native filesystem support. The Builder silently omits the actual native xattr. This is a **material metadata-fidelity loss** under the default non-reproducible builder contract for the tested native Mac environment, not a claim of lost original content bytes. The historical macOS test was not a direct compaction test; the new OS-native control adds product causal evidence.

Transfer to product owners is recorded by [issue #753](https://github.com/FCMO-AI/.CMPCT/issues/753). Existing [O65 #420](https://github.com/FCMO-AI/.CMPCT/pull/420) and [O72 #428](https://github.com/FCMO-AI/.CMPCT/pull/428) already discuss missing CPython Mac xattr methods: their existing ownership is prior art and must be reconciled rather than duplicated. #745 owns compaction; same-UID publication remains independently falsified in [#749](https://github.com/FCMO-AI/.CMPCT/pull/749).

## Falsifiers, controls and limits

A distinct macOS version, Python build or filesystem may expose different methods, so observed environment scope is explicit. A restored native provider must demonstrate real set/list/get, authentic Builder capture, read/verify, actual extraction restored bytes, symlink and binary-name/attribute semantics, plus compaction and end-to-end three-platform preservation, with source/CI fingerprints. Unsupported xattrs must never be represented as successful exact capture without an explicit contract limitation. macOS native CLI is a **research oracle only**, not an accepted subprocess hot-path implementation.

No native Win32 ADS, ACLs, large corpus, same-UID security, physical frozen benchmarks, cold open, RSS, CPU, temporary I/O, competitor or formal release parity is credited. The tiny Linux archive byte count does not imply gain. No release or merge. `docs/discovery/STATE.json` untouched under #574 coordination.

## Counterfactual / policy lesson

A two-line prospective `hasattr(os, 'setxattr'/'listxattr')` capability witness before seeding a required xattr fixture would have classified the historical macOS red immediately, avoiding repeated misattribution to compaction. However, that capability test alone would not show that native **OS** metadata existed and CMPCT lost it; the independent `/usr/bin/xattr` set/read/list control is decision-changing. This is a specific evidence-design lesson, not sufficient repeated evidence to mutate the shared Discovery Engine policy. Original strict historical tests preserved, no proxy green.
