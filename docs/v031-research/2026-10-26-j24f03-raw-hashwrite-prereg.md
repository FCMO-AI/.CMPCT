## Primary scientific question
Under an explicitly **mutable same-inode CMPCT archive source** threat model, can a separate writer change a physical RAW blob *after* the Reader has SHA-updated its logical digest from a zero-copy mmap memoryview but *before* its `os.write` to a private extraction stage, causing `extractall(metadata=False)` to report success while publishing wrong bytes?

## Observed baseline and mechanism
Authentic `_extract_chunked_verified` chooses `raw_direct` when every physical chunk codec is RAW; `_raw_blob_view_for_extract` returns a borrowed `memoryview(self.mm)`. Per chunk `digest.update(b)` precedes `os.write(fd, memoryview(b))`, and the final SHA is checked against the indexed logical commitment after all writes. A read-only mmap's bytes can reflect another permitted writer modifying the mapped source inode; hash-state custody is not necessarily byte-custody. The expected adversarial gap is the interval between `digest.update` and `os.write`.

## Strong controls and possible alternative explanations
Construct **independently handwired** revision-24 dual-index archive records with 3 distinct RAW physical chunks, both S_CHUNKS and S_CDC mappings. Use package Zstd only to compress the authenticated MessagePack index; do not use Builder. Before mutation: verify complete archive SHA, Reader.read() exact logical bytes, Reader.verify() success and ordinary extraction exact. Use a **separate process** permitted to write the archive inode, synchronized at the real Reader's first stage os.write *after* SHA update. It changes only the physical RAW payload range, not the index or staging directory. Require distinct process PID and unchanged file length/inode, and confirm only expected physical bytes changed. Interception may synchronize a syscall, but must not change Reader implementation or its actual os.write path. Independent prospective causal control: write a bounded immutable snapshot `bytes(view)` instead of a mutable view in a detached micro-control; the same source mutation must not change copied bytes. A third possible explanation is OS mmap coherence not providing the expected changed bytes on one host; classify HOST_SCOPED/NO_REPRO rather than infer.

## Prediction and decision thresholds
`VULNERABILITY_REPRODUCED` only if both S_CHUNKS and S_CDC, on both Ubuntu 24.04 and macOS 14, have: (a) ordinary same-source unmutated exact extraction, (b) new child writer changes first physical payload after first original `digest.update` and before stage write, (c) *real unmodified installed Reader* returns success, (d) published output length matches signed logical size but SHA differs from signed whole-file SHA and matches expected altered payload, (e) source inode remains same while archive SHA changes, (f) no stage namespace pivot. `HOST_SCOPED` if only one platform; `NO_REPRO` if original refuses or still publishes original; `INCONCLUSIVE` on source/fixture identity, hook, actor or validation problems. Decisive result informs ownership boundary in hash-to-write stream. No prevalence, remote adversary, release or whole-archive authenticity claims.

## BONK: cheapest evidence
Reasoning plus standalone `mmap.ACCESS_READ`/external `pwrite` already demonstrated Linux source view changes between hash/write, but is **mechanism micro-proof only**, not authentic product proof. Strong simpler control is copying one bounded chunk prior to hashing/writing. Headroom is integrity/safety, not compression speed. Two independently encoded shapes on hosted POSIX runners are the cheapest genuine product fork; no 4GiB benchmark, no alternate encoder or format change. If true, owner should couple authenticated bytes to written bytes (e.g. per-chunk immutable copy) while retaining logical SHA and accounting extra copy/RSS; or declare a precise immutable-source contract and enforce it. If false, retire narrow mechanism and return to a different frontier.

## Invariants, scope, cost and failure transparency
No shipping source edits, format/ABI/release bump, benchmark/comparator/threshold alteration, or unsafe existing-path mutation; all attacker activity limited to disposable synthetic local archives. Original source is deliberately mutated *during attack*, unlike J24F02's intact source, and must be explicitly reported as such. Static ordinary extraction and corruption controls must stay authoritative. No performance/RSS benefit asserted; extra per-chunk copying is only a future candidate, whose full cost is unmeasured. Hardened caller/system could prevent mutation via permissions or snapshots; this experiment does not claim adversary privilege other than authorized same-inode write.
