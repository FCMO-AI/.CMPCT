## Primary question and expected value
Does Windows `CreateFileW` with `FILE_FLAG_OPEN_REPARSE_POINT` plus an opened-descriptor physical identity and read provide the same *actual source bytes, type admission and hardlink topology* as current O47's two-name-based operations, **without following a final symlink**, at a lower cost on 256 independent small regular files? J24I13 found +23.10% end-to-end Builder create cost with extra pathname metadata, and its original standard `open()+fstat` route saved 32.16% in a micro but was *unsafe* when a symlink became the source. This court is a distinct security-preserving alternative, not a new Builder implementation.

**Preregistered prediction:** Win32 non-following open returns a handle whose `FILE_ATTRIBUTE_REPARSE_POINT` is visible before reading; reject source symlink, including a symlink that targets an unrelated readable file. A single source handle should identify genuine two-name hardlinks as one physical owner, and a byte-identical copy as independent. With source SHA and topology equal, non-following Win32 handle-read may beat O47 source `os.stat(nofollow)+open/read` in at least 3/4 paired ABBA rounds by **>=10%** on 256 unique files; the performance hypothesis fails if the bar is not reached. Exactly equal content hashes are insufficient if hardlink physical identity differs. An unavailable Win32 API or host privilege is reported as infrastructure/portability, not a product loss.

## Strong controls and incompatible alternatives
A = established O47-class `os.stat(path, follow_symlinks=False)` then ordinary read (same-input source identity baseline). B = `CreateFileW(FILE_READ_DATA|FILE_READ_ATTRIBUTES, share READ|WRITE|DELETE, OPEN_EXISTING, FILE_FLAG_OPEN_REPARSE_POINT)`, authenticating reparse attributes on that handle, deriving identity/size/link count from `GetFileInformationByHandle`, then reading *the same handle* through msvcrt/CRT. B must close exactly once on errors. A/A uses same A pathway under both labels, ABBA in four rounds, raw wall/process CPU per sweep. Strong simpler control: existing O47 remains correct for static source topology; simple `open()+fstat` is faster but already proven unsafe.

## Semantics, hostile witnesses and kill conditions
Test separately: independent 256 regular files, owner/alias/copy triple with exactly one hardlink relation, final symlink to a real file that must be **rejected before any content read**, and a directory or nonregular leaf that must not be mistaken for a regular owner. Windows file IDs and hardlink count come from the *opened* handle rather than a second pathname stat. Contrast raw/normalized mode and physical owner identities with O47 original controls. Name the limit: `FILE_FLAG_OPEN_REPARSE_POINT` only constrains the final path component; parent-directory junctions/symlink pivots and source-content mutation after open are NOT solved. Never claim whole-tree source-root containment or snapshot consistency from this experiment.

**Hard kill:** any followed symlink, outside-byte observation, misclassified alias/copy, unexpected data mismatch or leaked/invalid handle; also reject economic promotion if fewer than three of four ABBA rounds clear the threshold. Record Windows-host API errors and legitimate limitations without weakening the test. If the safe path loses, do not threshold-garden: retain O47 and investigate root/parent descriptor or a product-safe ownership change rather than a near duplicate. If positive, this earns only a bounded product prototype proposal plus real Builder and adversarial root/parent/metadata + recovery/perf gates.
