# J24I63 — Native verify of an already-open same-inode replacement

2026-10-30 UTC; prospective preregistration BEFORE source/test changes. Base #844 `399e9ab3f4f1c130d1ec448b4f0686abf84b2e0b`; release v0.30.0 / r24 unchanged.

Hypothesis: `Archive::open` caches decoded primary entries but not the authenticated index digest. `verify_complete` re-reads header and tail from the held descriptor. Replace the same inode after open, before verify, with a separately valid single-generation r24 archive with equal-size index compression/geometry and different authenticated path but unchanged physical payload: the old handle may incorrectly return SUCCESS authenticating its old cached entries against the new header/tail. Simpler control: both A and B independently pass native ABI/CLI and Python Reader; different member path, same inode, exact byte length. Prepatch predicted outcome: held A returns SUCCESS while fresh B verifies a different name. Alternate explanation: a geometry mismatch/invalid B (must reject that experiment, not credit it).

Proposed bounded fix after reproducing: capture the index digest on open and compare with the held header inside complete-verify before counting members. Disproof: no prepatch witness, invalid B, count not reset, fresh B rejected or inherited original/signed-generation tests broken. Preserve exact-head negative and positive evidence. This is stable mutation between calls, NOT an atomic concurrent snapshot. No public ABI/format/version/release gate changes; only 32 bytes of reader-local state and an already-read digest comparison. #844 owns latest signed-generation veto; #807 owns ABI; do not edit their branches or discovery state.
