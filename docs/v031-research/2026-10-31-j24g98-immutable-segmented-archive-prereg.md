# J24G98 — Immutable segmented archive publication O0 (preregistered 2026-10-31 UTC)

**Scope:** research-only, physical-organization counterframe to #869 two-store trusted-head cuts. No product/format/release/benchmark/Reader/Writer mutation. This document is committed before the J24G98 instrument and before any segmented archival measurements.

## Authority and baseline
Published main `80c358f8824ec1b20d349c92ed94c898090969b0`, v0.30.0/r24. #869 showed that independently publishing an in-place append and a separately pinned head creates a two-store crash-cut ambiguity; #866 showed a trusted whole-file SHA needs immutable consumed bytes. #853/#856 hosted original physical r24 files give 4- and 64-footer histories with true last-append bytes. They are inputs, not fixtures to optimize by name. This candidate addresses **ownership/publication**, not footer encryption or a new chain hash.

## One primary question
Can a single atomically switched manifest of **immutable archive fragments** represent genuine append histories byte-for-byte with O(new segment bytes) content copying and cheap random access, without the physical-allocation and FD explosion of one file per transaction? This is a *physical organization O0*, not an integrated Reader or power-loss guarantee.

## Predicted outcomes and predetermined decision boundary
- On all eight authentic provider-SHA-verified source histories, reconstruct the original entire r24 byte stream from a base prefix and one immutable delta segment per confirmed footer. Every logical byte and SHA-256 must match the real original, including each intermediate footer prefix; reject missing/tampered segments and bad manifest lengths/hashes. No CMPCT import. The unchanged contiguous file is the stronger correctness control.
- Expected: per-append logical new payload ranges are small (~97B for deep DELETE histories); the fragment layout avoids O(archive-size) content-copy amplification of retaining full immutable archives, but one file per footer pays block-rounded physical allocation, directory-entry/inode overhead, manifest bytes and O(history-depth) open/seek work.
- **Kill O1 one-file-per-footer route** unless (a) exact reconstruction succeeds for all inputs, (b) at depth 64, filesystem allocated bytes of fragments plus bounded manifest are <=1.05 times a same-directory contiguous copy of the exact same file (including one active manifest), and (c) warm 4KiB random-read p50 is <=2x single contiguous-file p50 on the same runner after equal authentication preconditions. Record each condition independently. This intentionally strict local criterion is a feasibility filter, **not a release gate** and cannot prove universal impossibility.
- Stronger simpler control: original in-place 97B append (best byte efficiency, weaker independent immutability). Opposite ownership control: copy entire prefix into a new immutable version per generation (one-file fast reads, O(prefix bytes) copy). Optional Linux FICLONE CoW must be reported as available/unavailable, not assumed or silently counted as free. Never compare the extra manifest hash to an unattested original without noting the trust boundary.

## Cost / hostile controls
On the current local filesystem report `st_size`, `st_blocks*512`, segment count, manifest bytes, total bytes created, actual work to materialize, peak allocation proxy, random-read latency raw samples, max number of simultaneously open files, and a held-read snapshot under a manifest switch. Test corruption of each selected data component and of manifest length/digest; reject path traversal and duplicate/missing extent IDs. Deleting an unreferenced generation must not destroy the current one. A mode-0444 file is NOT immutable against its owner; demonstrate/read this negative without overstating security.

No O0 credit for real crash durability, arbitrary concurrency, CI portability, whole Reader integration, fsmeta/hardlinks, source trust, CAS, power failure, or cold disk. Ordinary `rename`+directory fsync claims are limited to normal-process visibility; a staged interruption is not a power cut. If physical block allocation kills the representation, retain result as a narrow negative and compare how a larger authenticated segment/epoch or filesystem-supported reflink could change the bound, without implementation sprawl.
