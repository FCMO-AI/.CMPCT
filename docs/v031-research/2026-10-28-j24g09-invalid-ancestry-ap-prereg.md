## Primary question / mechanism
Can a *compressed proof of exact visited invalid footer offsets*, rather than a larger set cap, eliminate the 16,384-entry cliff for uniformly spaced SHA-authentic orphan chains while preserving the Reader's original fallback, nearest valid footer selection, and memory accounting?

The #650 scan visits an invalid ancestry and proves no checkpoint is reachable from each visited node, under a stable archive source. Its entire set fails admission when above 16,384 entries. One general discoverable subclass of invalid ancestry has offsets forming an exact arithmetic progression `start + k * stride`. The proof consists of *all* visited integer positions sorted, exact cardinality, and exact stride; it must never infer membership merely from min/max, magic, fixture identity, checksum-free guessed geometry, or a lossy bloom filter. Store at most 32 such triples per open, with only exact step-aligned membership as a pruning certificate. Successful chains are NEVER memoized. Keep existing #650 set behavior for smaller/nonmatching chains. Invalidating the certificate when its input archive can mutate is a separate unsolved consistency contract (#654); do not pretend to solve it.

## Prospective predictions and decisive controls
- Constant-81-byte record linked orphan tail with N=16,384 and 16,400 after a real Builder checkpoint: baseline #650 call counts 16,385 and 278,665; candidate predicts exactly N+1 decoder calls (16,385 and 16,401) and identical selected checkpoint, read/range/verify. The 16,400 row is the primary decisive falsifier and must be measured on the *genuine installed candidate*.
- N=32,768 constant-stride extended tail: candidate predicts 32,769 genuine calls and valid fallback (not ~134m calls); use a separate source-bound script with generous upper execution bounds rather than running old baseline to exhaustion. This is a held-out N, not a new codec benchmark.
- Same-byte flat orphan control with N=16,400 (no chains): N+1 actual decoder calls; no size/wall penalty beyond timing noise from the extra certificate branch; full archive bytes fixed.
- Non-arithmetic malformed ancestry and syntactically plausible magic at unvisited offsets: do not infer interval validity. Require exact coverage, safe ordinary replay, and no silently skipped valid footer. A cheaper small simulated/referee check can falsify the membership logic before expensive CI.
- Legitimately rooted committed generation and historical original archive: strict same-file semantic identity and no changed format/Builder/Writer/validator or release fingerprint. If the candidate cannot select older original checkpoint exactly, **KILL**; if its new interval admits any offset not previously authenticated/visited, **KILL**.
- One-archive operation-scope only, max 32 triples (three Python ints each), no persistent cache. Record actual decoder calls, library wall, CPU, artifact physical bytes, content SHA, selected generation, and use independent ZIP/receipt checks where possible. Memory claimed only as structural bound on certificate count until peak RSS is actually measured.

## Alternatives and limitations
Increasing `known_bad` above 16k exports unbounded Python-set memory; prefix-only admission was disproved analytically at N=32,768 in #655. A global depth abort (#365) rejects previously recoverable older committed generations (#658). Full external spill/index may provide broader guarantees but exports temp I/O and complexity. Arithmetic-run exact certificates cheaply test *whether a bounded proof compression frame is viable*; they **do not solve** arbitrary nonuniform/sparse/interleaved ancestry or concurrent in-place source mutation. A positive local test earns only a narrow rehabilitated candidate; global hostile-input work limits and process costs remain required for promotion.
