This yields a stronger root-cause falsifier for a naive fix that only forbids `.`/`..`/casefold collisions among raw names.

## Scientific decision, strongest negative, counterfactual, next action
**Decision changing:** simply tightening raw ZIP name grammar and normalizing casefold paths is insufficient as a universal *installed-native ownership* attestation: the standard wheel `.data/purelib` install phase creates collisions between differently named, well-formed ZIP members. A correct admission policy must either explicitly restrict its guarantee to physical ZIP+Mach-O+RECORD (and keep separate installed-artifact provenance checks) or model/verify the **complete pip installation destination projection and uniqueness**, including .data spread and relevant filesystem equivalence. An exact installed-native SHA check after installation (already built in #850) is a strong simpler shipping control, with the source wheel hash and intended native hash both bound. Do not build a second owner validator here.

The strongest self-critique: a malicious wheel can already replace code by directly changing and rehashing the native member; this court does NOT demonstrate an attacker bypassing a publisher signature or installing malicious CMPCT in users' systems. It demonstrates that **the physical gate may attest the wrong native bytes after a legitimate installer transforms an internally self-consistent wheel**, unless destination identity is included. A second negative: the J24P05c unique-stale-row prediction was **falsified**, so all such claims must be corrected to duplicate-rows instead of retroactively considered confirmed. J24P05d is only local Linux cross-target; hosted macOS source exact is pending if future resource allocation makes it decision-changing.

**Counterfactual discriminator:** inspect PEP 427 `Unpack → Spread` destination mapping and canonical aliases before treating raw ZIP member uniqueness as installed-file uniqueness; this single necessary structural check would have falsified this whole family without exhaustive wheel rebuilding. A policy-level Discovery change is not earned from one instance.

Owner #854 notified with the two-host evidence; product publishing integration belongs #850. No main/owner code, Discovery STATE, releases, frozen benchmarks, comparators or promotion gates were changed. **Product/release credit zero.**
