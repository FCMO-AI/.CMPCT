## Predictions, controls and kill/narrow rules frozen before implementation
1. **P1, memory/decision:** For 200,000 one-key tiny maps encoded in ~800 KiB, a structural count bound at 65,536 nodes must terminate before `msgpack.unpackb`, with peak *additional* Python allocations far below the 33.66 MiB J24G15 materialization delta. Demonstrate using matched fresh child processes, not RSS inherited from parent generation.
2. **P2, exact semantics:** Every below-budget valid MessagePack payload in held-out scalar/array/map/bin/str/ext/UTF8 test vectors must remain accepted by unchanged `msgpack.unpackb`. Every below-budget malformed payload must be rejected by unchanged `msgpack.unpackb`; the scanner is a *necessary admission only, never proof of validity*. A false scanner refusal of an otherwise valid under-budget payload kills the implementation. A malformed nested-key accepted by the scanner is expected but MUST fail in the original decoder.
3. **P3, economics:** On admitted ordinary metadata-like payloads, the extra scanner's median process-local decode wall time should be ≤2.0× direct unpack. If >2.0×, retire this **pure Python** scanner as the default Reader route even if P1 holds; preserve its bound proof as a possible native/preflight architecture.
4. **Strong simpler controls:** plain `unpackb` (current), `Unpacker.skip` (potential fastest C-backed but cannot certify aggregate tokens/semantics alone), and object/list hooks (can reject after construction, cannot generally limit aggregate child allocations).
5. **Adversaries:** equal-size opaque vs 200k-map, 200k flat atomics, 4k×50 nested arrays, repeated shallow short maps, a nested unhashable map key, truncated and extra trailing bytes, ext markers, and randomized structured payloads.
6. **No relaxed semantics:** Exceeding the *research-only* node limit produces an explicit resource refusal, not silent recovery or acceptance. Such a refusal changes today's accepted input domain; no product promotion is authorized before a separately justified resource-policy decision, Reader recovery/fallback and three-host release proof.
7. **Scientific rung:** This is a synthetic signed-risk mechanism/oracle and local/hosted microcourt, not current whole-CMPCT Reader proof. No bytes/create/read/extract/product-memory credit, no general implementation until the fork is earned.
