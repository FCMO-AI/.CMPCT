## Problem, hypothesis, control, alternatives
Owner #287 solves real speculative-state leakage after late valid-but-unreproducible Deflate and preserves successful VZIP semantics. But its per-hash metadata journal snapshots existing hints and Deflate multiplicities. A local source-semantic microprobe on 8000 tiny hashes suggested 1.07–1.79× callback overhead for successful probes depending on preexisting candidates, with additional ~349B temporary tracemalloc memory per previously touched key at 50% reuse; these are NOT CMPCT measurements. The next cheapest useful fork: **does that overhead matter in authentic Builder end-to-end creation on held-out ZIP-rich inputs, compared same input and same source semantics?**

O1 is a diagnostic ABBA on a single reproducible corpus per regime using the original exact-source **base** Builder and exact-source **candidate** Builder, each with the **same Reader/format**. A source contains many unique synthetic ZIP_STORED files and optional identical preexisting loose member files (to force reachable-candidate metadata mutations). Last ZIP entry is either compatible standard DEFLATE (successful VZIP) or valid nonreproducible RFC1951 Z_FIXED (late opaque fallback). A full compressed-source SHA fingerprint and bytewise input parity are mandatory; choose at least two regimes, successful and rejected VZIP, with a preexisting-alias stress. The full file tree/ZIP must not differ between A and B. No after-the-fact tuning to promote favorable metrics.

Strong control is exact official PR #288 performance (frozen public parity corpus). O1 complements but never supersedes it. Cheap alternatives (another dictionary-only synthetic callback microbench, another real VZIP implementation, changing compression levels/thresholds, rerunning historical benchmarks with two different random corpora) cannot answer this decision. No new Builder mechanism is developed here.

## Prediction / kill conditions
Predicted: late reject candidate complete archives are <= base archive bytes for the same input (potentially strictly smaller owing to discarded speculative blobs); success VZIP output is byte-identical. Candidate may incur measurable Python metadata cost, more visible with high distinct first-member count/preexisting candidate aliasing. Run at least ABBA with repeated raw timing observations, product archive SHA/bytes, exact Reader.verify/read and source hashes. Record CPU/wall and process RSS where supported; do not mix import/setup wall with library execution.
**Narrow/kill journal-economics optimism** if candidate suffers confirmed material end-to-end create/RSS regression without offsetting correctness/size benefit; preserve scientifically valid fix as safety seed rather than weakening consistency. **Kill O1 evidence** if either authentic Builder/Reader cannot run, if independent source hashes mismatch, if outputs cannot be read exactly, if the valid ZIP oracle is not genuinely late-nonreproducible, or if run order/host differences make causal attribution impossible. Don't infer product advantage from one trial, workflow success with skipped tests, or input-conditional archive differences on unlike corpora.
